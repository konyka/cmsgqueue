# CMSGQueue v0.5.4 — Remaining Gap Enumeration

**Scope.** Items deferred from v0.5.3 (which shipped 12/12 P-items) plus
any new gaps at HEAD (v0.5.3, commit 5a874d4, 68/68 tests, ~32K msg/s).

## Sources

- `docs/reviews/v0.5.3.enumeration.md` — adversarial 13-item catalog.
- `docs/reviews/v0.5.3.plan.md` — 4-phase WBS (12 P-items shipped).
- `src/enterprise/cmq_mqtt_server.c:545` — relay-thread placeholder
  (relay emits a debug log; sublist_insert deferred to v0.6).

  but only slot[0] wired at runtime.

## P1 — F19b full bridge: relay → sublist_insert

- **gap** → `src/enterprise/cmq_mqtt_server.c:441` (the relay
  thread dequeues the bridge payload but does NOT call
  `cmq_sublist_insert`; line 444 is a `(void)topic` no-op) →
  **impact**: mqtt PUBLISH topics never reach cmq subscribers; the
  v0.5.3 "plumbing" was a no-op under the hood → **effort**: M
  (sublist insert under srv's per-listener lock; per-topic
  `cmq_sub_ref_t` allocation; cleanup on disconnect).

## P1 — Multi-listener slots[1..3] wired at runtime

- **gap** → `src/server/cmq_server.c:7014-7040` (cmq_server_run
  binds a single listen_fd from the legacy port; only slot[0] is
  used) → **impact**: cannot serve two certs/ports from one process;
  the slot[] array and cmq_rch handles exist but are unreferenced
  by the accept loop → **effort**: M (200 LOC accept loop iterates
  slots[0..n-1], each binds its own fd, per-listener TLS context).

## P1 — 5.0 properties decode on PUBLISH/SUBSCRIBE

- **gap** → `src/enterprise/cmq_mqtt_server.c:381-396` (CONNECT 5.0
  property length region is skipped; PUBLISH/SUBSCRIBE 5.0 property
  region not parsed at all) → **impact**: 5.0 clients can't send
  response_topic, message_expiry_interval, user_properties → **effort**:
  M (variable-byte length decoder, property type tags).

## P1 — cmq_tls_reload UAF on in-flight SSL*

- **gap** → `src/enterprise/cmq_tls.c:302` (SSL_CTX_free(old) is
  called immediately inside cmq_tls_reload; an in-flight SSL* from a
  client mid-handshake still references the old CTX) → **impact**:
  process crash under high connect churn; potential security
  regression → **effort**: M (refcount the SSL_CTX, free when last
  SSL* drops; v0.5.1 P1 reload refcounting already gives us the
  pattern via `cmq_rch_t`).

## P2 — MQTT relay-thread clean shutdown

- **gap** → `src/enterprise/cmq_mqtt_server.c:436` (the relay wakes
  on `g_mqtt_bridge_not_empty`; the only exit path is the global
  `g_mqtt_bridge_dying` flag, but there is no public
  `cmq_mqtt_bridge_shutdown()` and the listener's pthread_join
  doesn't wait on the relay) → **impact**: in-flight bridge
  payloads are lost at process exit → **effort**: S (add the
  shutdown function + call it from cmq_server_destroy).

## P2 — Async WAL ring payload bound (1024) too small

- **gap** → `src/enterprise/cmq_mqtt_server.c:572` (if
  `payload_len > 1024` the bridge silently drops) → **impact**: large
  mqtt payloads don't bridge → **effort**: S (heap-allocate the
  payload, free on relay drain).

## P2 — QG dedup 2-level hash for same-subject dedup

- **gap** → `src/server/cmq_server.c:1940` (per-entry hash check
  reduces O(n²) but for K members of the same (subject, qg,
  account) triple, all K entries share the same hash and trigger K
  full strcmps) → **impact**: still up to K-1 strcmps per
  publish → **effort**: M (per-snapshot secondary hash on subject
  only; same-subject members of different qg can be further
  de-duplicated).

## P2 — sublist_match under concurrent mutation

- **gap** → `src/server/cmq_sublist.c` (cmq_sublist_match
  traverses the trie without a lock; concurrent subscribe/unsubscribe
  during a publish could see torn entries) → **impact**:
  inconsistent delivery → **effort**: M (rdlock around match;
  pthreads rwlock on the sublist).

## P3 — MQTT listener default plaintext + no auth

- **gap** → `src/enterprise/cmq_mqtt_server.c:608-622`
  (cmq_mqtt_server_start_listener always binds 127.0.0.1:1883
  plaintext; g_mqtt_user defaults to "") → **impact**: anyone on
  the host can publish/subscribe; default should be "off" with
  explicit opt-in → **effort**: S (default-bool `enabled` flag;
  refuse to bind if not explicitly enabled).

## P3 — cmq_tls_set_crl still allows NULL path silently

- **gap** → `src/enterprise/cmq_tls.c:240-251` (if `crl_path` is
  NULL the field is cleared but no log; same for empty string) →
  **impact**: misconfig silent → **effort**: XS (add a log line).

## P3 — stat_async_enqueued missing

- **gap** → `src/store/cmq_filestore.c` (stat_async_blocked was
  added in v0.5.3 but stat_async_enqueued, the total successful
  enqueues, is not tracked) → **impact**: ops can see stalls but
  not throughput → **effort**: XS.

## P4 — QoS2 retransmit table cleanup on disconnect

- **gap** → `src/enterprise/cmq_mqtt_server.c:108` (g_qos2[] grows
  monotonically; never reset between MQTT sessions) →
  **impact**: long-running process accumulates stale packet_ids →
  **effort**: S (clear table on CONNECT; bounded by MQTT_QOS2_MAX).

## P4 — g_mqtt_sub_topics table also monotonic

- **gap** → `src/enterprise/cmq_mqtt_server.c:96` (g_mqtt_sub_count
  never decrements) → **impact**: same as above; subscribers grow →
  **effort**: XS (clear on CONNECT).
