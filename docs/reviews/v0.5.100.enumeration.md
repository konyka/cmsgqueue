# v0.5.100 — Request spans (D1 follow-up)

## Scope
`KIND_PUBLISH` / `KIND_CONSUME` / `KIND_CONNECT` are on the
ring. `handle_request` never offers a span. This increment
adds `KIND_REQUEST` and offers one after a successful
local answer.

## Design (performance-first, safety, reliability)

- One request span per successful local answer, not per
  responder.
- Same 16-byte accept `trace_id`.
- Local store reply (KV / OBJ / `$JS` get or pull) that
  sends a frame: one span.
- Local fanout `n > 0`: one span.
- No responders / encode fail / CONNACK-style error: no
  span. Route-only forward does not count (align consume).
- `otel == NULL`: no-op.
- Offer stays non-blocking; drop-newest unchanged.
