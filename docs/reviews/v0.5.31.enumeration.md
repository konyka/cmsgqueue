# v0.5.31 — Per-listener TLS runtime

## Scope
v0.5.18 ships a multi-listener runtime that binds multiple ports.
v0.5.30 verifies the cache isolation invariant. v0.5.31 wires
per-listener TLS so each listener can have its own cert (and the
session cache is naturally per-listener as a consequence).

Currently `cmq_server_create` only allocates `tls_config_slots[0]`.
v0.5.31 also allocates slots 1..3 when `cfg.listeners[i]` has its
own cert/key. The accept callback then picks the right TLS config
based on which listen fd accepted the connection.

## Design (performance-first, safety, reliability)

### Allocation (in `cmq_server_create`)

For each `i` in `1..min(listener_count, CMQ_MAX_LISTENERS)`, if
`cfg.listeners[i].tls_cert && cfg.listeners[i].tls_key`, allocate
`srv->tls_config_slots[i]` and load the cert/key. Slots without
both cert and key are skipped (listener uses slot 0's TLS, or
plaintext if slot 0 is also unconfigured).

### Per-connection TLS selection (in `accept_cb` / `client_tls_handshake`)

Add `int srv_find_tls_slot(cmq_server_t *srv, int listen_fd)` that
returns the slot index for a given listen fd, or -1. The accept
path stores the slot on the new `cmq_client_t` (we already have
`client->server`, so add `client->tls_slot`). The handshake path
uses `srv->tls_config_slots[client->tls_slot]`.

### Safety

- Slot allocation is per-listener: a failure in slot 2 doesn't
  unwind slot 1. Cleanup is already in `cmq_server_destroy` line
  7854 which iterates all slots.
- Cert/key validation: each slot's `cmq_tls_load` is checked; if
  it fails, the slot is destroyed and that listener falls back to
  plaintext (logged as a warning, not a hard error — a misconfigured
  listener shouldn't break the others).
- Back-compat: `cfg.listeners[0]` is mirrored by `cfg.tls_cert/tls_key`
  in the existing path; we keep that as slot 0.

### Reliability

- The accept thread (v0.5.17) iterates `listen_fds[1..N-1]`; each
  one must look up the right TLS slot via the same `srv_find_tls_slot`.
- Connection struct lives across threads, so `client->tls_slot` is
  set during accept (single-threaded at that point) and read during
  handshake (which may be in a worker thread). No atomic needed
  because the value is set before the client is published.

## Risk
- The accept loop is performance-critical. Adding a small
  listener-fd-to-slot lookup (linear scan over at most 4 entries)
  is negligible (~ns).
- The back-compat: existing callers that don't use `cfg.listeners`
  (just `cfg.tls_enabled = 1`) must still work. Slot 0 is allocated
  from the legacy fields; slots 1-3 are allocated from `listeners[]`.
  If a slot is unallocated, the listener falls back to slot 0
  (or plaintext if slot 0 is also unallocated).
