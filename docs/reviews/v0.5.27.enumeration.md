# v0.5.27 — TLS session cache OpenSSL callback wiring

## Scope
v0.5.23 implemented the session resumption cache as a standalone
module (`cmq_tls_session_cache.{c,h}`). The cache is fully testable in
isolation (6 unit tests) but **not yet wired to OpenSSL** — every TLS
handshake still does a full key exchange because the cache is never
consulted.

v0.5.27 wires the cache into OpenSSL's session lifecycle via
`SSL_CTX_sess_set_new_cb` (called when a new session is negotiated)
and `SSL_CTX_sess_set_get_cb` (called when a client presents a session
ID for resumption). With this wiring, a reconnecting client skips
the full key exchange and the handshake completes in ~1 round-trip
instead of 2.

## Design (performance-first, safety, reliability)

### Callback functions (new in cmq_tls.c)

```c
static int cmq_tls_sess_new_cb(SSL *ssl, SSL_SESSION *sess);
static SSL_SESSION *cmq_tls_sess_get_cb(SSL *ssl,
                                          const unsigned char *id,
                                          int id_len, int *copy);
```

- `sess_new_cb`: called by OpenSSL after a successful handshake with
  the freshly-minted `SSL_SESSION*`. We extract its session ID via
  `SSL_SESSION_get_id()`, insert into our cache (which takes ownership
  via `SSL_SESSION_up_ref`).
- `sess_get_cb`: called by OpenSSL when a client presents a session
  ID in the ClientHello. We look it up in our cache and return the
  cached `SSL_SESSION*` (or NULL on miss). OpenSSL does NOT take
  ownership — we return a borrowed reference. OpenSSL internally
  refcounts; we don't need to up_ref here.

### Wiring

In `tls_build_ssl_ctx` (the per-listener context builder), after the
cert/key load and ALPN/CRL setup, add:

```c
SSL_CTX_sess_set_new_cb(cfg->ssl_ctx, cmq_tls_sess_new_cb);
SSL_CTX_sess_set_get_cb(cfg->ssl_ctx, cmq_tls_sess_get_cb);
/* Disable OpenSSL's internal session cache; we own it. */
SSL_CTX_set_session_cache_mode(cfg->ssl_ctx,
    SSL_SESS_CACHE_SERVER | SSL_SESS_CACHE_NO_INTERNAL);
```

Also set a session timeout (default OpenSSL is 300s; keep that).

### Re-apply on reload

`cmq_tls_reload` (called when cert/key change) builds a NEW
`SSL_CTX*`. The callbacks must be re-registered on the new CTX.

### Safety

- `SSL_CTX_set_session_cache_mode(... NO_INTERNAL)` ensures OpenSSL
  doesn't maintain a parallel cache (would double the memory).
- Cache's `cmq_tls_session_cache_insert` returns -1 on failure
  (e.g., id too long) — the handshake still completes; we just don't
  cache that session.
- `cmq_tls_sess_get_cb` returning NULL tells OpenSSL "no cached
  session, do full handshake" — graceful degradation.

### Reliability

- Callbacks may be invoked from any pthread that does a handshake.
  The cache already uses `pthread_mutex_t` internally, so concurrent
  access is safe.
- If a cached session has expired (OpenSSL checks timeout), the
  callback returning it triggers a full handshake; cache is not
  corrupted.
