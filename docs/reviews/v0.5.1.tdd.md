# CMSGQueue v0.5.1 — TDD-First + Doc-First Workflow

**Role.** Workflow only — test scenarios and doc sections, not feature design.
**Test infra.** `tests/cmq_test.h` (`TEST(suite, name)`, `ASSERT*`, `TEST_MAIN()`),
CTest glob over `test_*.c`. **Shared loop:** doc-first (`## Design`+`## Tests`
written before code) → RED (`tests/test_x.c`, confirm expected failure) → GREEN →
refactor → `cd build && ctest --output-on-failure -j$(nproc)` → ASAN/UBSAN pass →
fill measured `## Verification gates` → atomic commit.

**Perf-regression gate (Round 3 refinement).** Behavior-only tests cannot catch
the perf architects' wins. Add `bench/` first: `bench_publish_latency`,
`bench_route_tls`, `bench_sublist_persist`, `bench_mqtt_listen`. Then
`tests/test_bench_regression.c` (gated behind `CMQ_ENABLE_BENCH`, excluded from
the default ctest glob so it cannot flake CI) measures p50/p99 publish latency
and msg/s over N iterations and asserts a hard floor: **≥30K msg/s, p99 ≤60 µs**
(tight enough to catch the 250–500 µs WAL stall, not flaky). Perf PRs must paste
before/after bench output in the commit body; the monotonic test fails on
regression. Perf claims are bench-measured; correctness is TDD'd.

**Security-derived RED tests (Round 3 refinement).** Fold the security review
findings in so the suite fails-before / passes-after each fix (7/8 findings).
The one non-testable race (reload UAF, ACL/blocklist) is routed to a TSAN/stress
harness + code-review gate, explicitly not a `cmq_test.h` RED test.

## F17 — Full BIO-wrap in cmq_route.c

**State.** `write_one`/`read_one` branch on a `sess` param (`cmq_route.c:174-192`)
but call sites hardcode `NULL` (`:102`, `:156`); no `cmq_route_tls_sess_create`
call in `src/`; `route_require_tls` config unread. Libs
`cmq_route_tls{,_sess}` exist, never wired.

**Test scenarios** (`tests/test_route_tls.c` + `test_route_tls_sess.c`):
- `route_tls.cleartext_disabled_when_configured` — `route_require_tls=1`,
  cleartext peer rejected at handshake.
- `route_tls.handshake_ok` — both peers configured → session established.
- `route_tls.handshake_fail_bad_cert` — untrusted peer cert → handshake fails.
- `route_tls_sess.echo_over_tls` — real-fd SSL round-trip (read/write/EAGAIN).
- `route_tls.cleartext_rejected` / `route_tls.handshake_nonblocking` — security
  findings #5: non-blocking handshake with poll timeout + partial-write mode
  (stalled peer must NOT hang the route worker).

**Doc sections:** new `docs/features/route-tls.md` (canonical 9-section
template) + ADR 0010. **Gate:** 6/6; handshake ≤5 ms (p50); **per-core route
thread CPU** via `getrusage(RUSAGE_THREAD)` on the route worker loop, sampled
over a fixed 10 s run at 10K msg/s TLS-on vs TLS-off — Δ(utime+stime) ≤5% of
wall time (this makes the F17 CPU gate concrete and measurable, Round 3);
full suite.

## N1 — Per-subject rate limit

**State (verified on HEAD).** Library `cmq_subject_rl` + server enforcement
already wired: `srv->subject_rl` created at `cmq_server.c:6708-6714`,
`cmq_subject_rl_check` in `handle_publish` `:2967-2973`. Gap is **coverage**
only: `tests/test_subject_rl.c` exercises the library (3 tests), not the server
path.

**Test scenarios** (extend `tests/test_subject_rl.c` or new `test_subject_rl_server.c`):
- `subject_rl_server.zero_limit_admits` — `max_msgs_per_sec_per_subject=0` → no
  rejection.
- `subject_rl_server.enforced_in_handle_publish` — limit=3, 4th publish gets
  `cmq_send_error("subject rate limit")`.
- `subject_rl_server.per_subject_buckets` — two subjects don't share a bucket.
- `subject_rl_server.counter_increments` — `stat_publishes_rejected` bumps on
  rejection.
- `subject_rl.concurrent_no_bypass` — N threads × K msgs on one subject; assert
  admitted count ≤ limit (catches security #2: non-atomic `count++` + lost
  buckets under concurrency).
- `batch_rl.acl_quota_rl_applied` — BATCH frame carrying a subject over
  ACL/quota/RL caps → rejected entries (catches security #3: `handle_batch`
  skips all three gates; WAL append before checks at `cmq_server.c:2940`).

**Doc sections:** new `docs/features/subject-rate-limit.md` (9-section); config
field documented in `README.md`/`cmq_config` section. **Gate:** 4/4; full suite.

## mTLS — Client cert chain / CRL

**State.** `SSL_VERIFY_PEER` + `FAIL_IF_NO_PEER_CERT` set (`cmq_tls.c:293-296`);
no `SSL_CTX_set_client_CA_list` from the `ca` field, no custom CRL/OCSP.

**Test scenarios** (extend `tests/test_mtls_api.c`):
- `mtls_api.ca_list_set` — CA path populates the client CA list.
- `mtls_api.chain_rejects_unknown_ca` — client cert signed by an untrusted CA
  fails at handshake.
- `mtls_api.crl_path_accepted` — CRL path accepted at config level.
- `mtls_api.verify_peer_off_admits` — `verify_peer=0` still admits (no chain).
- `tls.verify_peer_requires_client_cert` — `verify_peer=1` handshake with no
  client cert fails (catches security #4: `tls_build_ssl_ctx` never calls
  `SSL_CTX_set_verify`; only `cmq_tls_reload` does, and the server calls only
  `cmq_tls_load`).

**Doc sections:** `docs/features/tls-hardening.md` mTLS/CRL subsection + ADR.
**Gate:** 5/5; existing mTLS tests green; full suite.

## WAL — Replay parallelization

**State.** `cmq_server.c:6647` `for (seq=1..last)` single-threaded O(N); no
parallelism; budget ≤10 ms for 100K subs.

**Test scenarios** (extend `tests/test_persist_unit.c`):
- `persist_unit.replay_parallel_consistent` — write N records, restart, restored
  state equals sequential-replay baseline.
- `persist_unit.replay_deterministic` — two runs yield identical restored state.
- `persist_unit.replay_partition_isolated` — subjects in distinct partitions both
  restore correctly.
- `persist_unit.replay_restores_messages` — server with `persist_dir`, publish
  N, destroy, recreate; assert N delivered to a subscriber. **Fails before**
  security #1 fix (replay_c `account_epoch=0` vs `$default` epoch=1 →
  `client_account_live` rejects every record), passes after.
- `audit.rotation_after_cap` — tiny `AUDIT_MAX_BYTES`, force events, assert
  `path.1` exists (catches security #7: per-event `fopen` means `ftell` never
  sees the real file size; path never wired from config).
- `quota.connect_limit_enforced` — server-level `max_connections_per_account`
  (catches security #8: `cmq_quota_check_connect` has zero callers).

**Doc sections:** `docs/features/persistence.md` replay subsection (parallel
design, order guarantee). **Gate:** 3/3; ≤10 ms/100K subs; full suite.

**Not testable (process gap, routed elsewhere):** security #6 reload UAF
(`cmq_server_reload` frees `server->acl`/`blocklist` with no reader lock while
workers read lock-free at `:2952`/`:4435`) is a race window the single-threaded
`cmq_test.h` harness cannot deterministically trigger. Cover with a TSAN build
(`-fsanitize=thread`) stress test + review gate on the reload swap; label it in
the plan as not a RED test.

## Doc template standardization

20/23 `docs/features/*.md` follow a 9-section template. Deviations:
`flag-rejection.md` (caps, `## See Also`/`## Verification Gates`, extra `## API`),
`tls-hardening.md`/`test-stress-flake-fix.md`/stub docs (`## Status`/`## Changes`).
Duplicate F-numbers across files; no doc states the run command.

**Canonical template:**

```
# <F/P>: <Title>
## Motivation
## Design
## Files touched
## Tests                 # exact names + counts
## Verification gates    # measured counts + the exact command
## Performance
## Security
## Limitations
## See also              # enumeration P# + sibling docs
```

**Tweaks:**
1. Normalize casing to `## Verification gates` / `## See also` (20/23).
2. Optional `## Status` (stub/follow-up) or `## API` (new public surface) after
   Design — body still follows the 9 sections.
3. `## Verification gates` must state the command
   (`./build/tests/test_x`, then `ctest --output-on-failure -j$(nproc)`), not
   just a count.
4. De-stub renames on implementation (`mqtt-server-stub.md`→`mqtt-server.md`,
   `sublist-persist.md`); update all cross-refs; no `(STUB)` titles at release.
5. Doc-first contract: `## Design`+`## Tests` before code; perf/security/
   limitations filled with measured data after green.
6. Disambiguate numbering — new docs use enumeration P-numbers or fresh
   sequential F-numbers; never reuse a claimed F-number.
