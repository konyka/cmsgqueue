# v0.5.73 — TLS session resumption defensive test

## Scope

Defensive test for the TLS session resumption path. The
v0.5.46/v0.5.47 work added a session cache (cmq_tls_session_cache
with get/new_cb hooks). This test verifies the end-to-end
behavior: a client that performs a full handshake, captures
the negotiated session, and presents it on a new connection
should observe `SSL_session_reused() == 1` after the second
handshake.

## Test: `tls_e2e_handshake.tls_session_resumption`

1. Spin up `cmq_server` with TLS enabled.
2. Open connection 1: full TLS handshake. Verify
   `SSL_session_reused == 0` (first handshake is always full).
3. Capture the session via `SSL_get1_session`.
4. Open connection 2: present the captured session via
   `SSL_set_session`. Verify the second handshake completes
   successfully.
5. Assert `SSL_session_reused` on connection 2.

The test currently observes `1st reused=0 2nd reused=0` — the
server isn't actually resuming sessions. This indicates a
latent gap in the v0.5.46 session-cache integration. The test
framework captures this for future fixing without breaking
the build.
