# v0.5.46 — MQTT will + durable sessions

## Scope
R6 from v0.5.41: the MQTT listener has no last-will store and no
clean-session vs durable session. CONNECT also maps the wrong
flag bits — `0x04` (Will) is copied into username and `0x02`
(Clean Session) into password.

Remaining P2 after this round: R7 connz/subz/routez.

## Design (performance-first, safety, reliability)

### Spec CONNECT payload

`cmq_mqtt_parse_connect` walks MQTT-3.1.1 / 5.0 §3.1:

```
client_id | [will props if v5] will_topic will_payload | user | pass
```

Flags: reserved `0x01` fail-closed; Will `0x04`; Clean `0x02`;
Username `0x80`; Password `0x40`. Strings borrowed from the
packet except copies we persist.

### Will

Bounded table (32). Store a malloc copy of topic+payload at
CONNECT. Fire on abnormal close (`recv <= 0`), not on
DISCONNECT. Optional retain uses the existing retain store;
bridge uses the same enqueue path as PUBLISH.

### Durable session

Bounded table (32 × 8 filters). Clean Session=1 drops the
slot. Clean Session=0 restores filters via
`cmq_mqtt_record_subscriber` and saves this connection's
filters on disconnect.

Hot cmq PUBLISH path unchanged.

### Safety

- Will payload capped at 4 KiB.
- Unknown v5 will properties fail CONNECT (existing decoder).
- Will/session tables are mutex-protected, fixed size.
