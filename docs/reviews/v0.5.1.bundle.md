## B. Convergent Findings (multi-member confirmed)

### B1. WAL replay is a silent no-op (CRITICAL)
- **Evidence:** `cmq_server.c:6668-6686` (replay_c zeroed, only name+server); `cmq_account.c:176` ($default epoch=1); `cmq_server.c:2817` (`client_account_live` requires `ep == c->account_epoch`).
- **Impact:** Every persisted message dropped on restart. The "Replaying N records … complete" log is a lie.
- **Latent:** naive epoch-stamp fix causes re-append duplicates at `seq > last` (last snapshotted before loop) → unbounded WAL growth + duplicate delivery.
- **Fix (perf-clean):** (a) stamp `replay_c.account_epoch` from live `$default`; (b) add replay flag, skip `cmq_filestore_append` in `handle_publish` during replay; (c) set `fd=-1, worker_id=-1` on replay_c (today `fd=0` → write to stdin if a rejected record falls to `cmq_client_send_direct`).

### B2. subject_rl + quota linked-bucket races (HIGH)
- **Evidence:** `cmq_subject_rl.c:40-53` (`find_or_create` mutates `rl->buckets` with zero sync); `:55-69` (`count++` non-atomic). Same pattern in `cmq_quota.c:40-52`.
- **Fix (perf-clean):** atomic fixed-slot open-addressing over `CMQ_SUBJECT_RL_SLOTS 4096` (declared, currently unused at `cmq_subject_rl.c:8`). FNV-1a hash → probe → `__atomic_fetch_add` on count, `__atomic` CAS on `window_start_ms`. Bounded probe (collision-accept, fail-open on probe exhaustion, matches existing `cmq_subject_rl_check` OOM behavior). Apply identical treatment to `cmq_quota_check_publish`.

### B3. BATCH bypasses ACL + quota + rate limit (HIGH)
- **Evidence:** `cmq_server.c:4037-4105` (`handle_batch` calls only `cmq_account_can_export`; grep shows `cmq_acl_check`/`cmq_quota_check_publish`/`cmq_subject_rl_check` ONLY at 2952/2960/2968 in `handle_publish`). WAL append at `:2940` happens BEFORE admission checks.
- **Fix (perf-clean):** per-entry gates in pass1 = O(count) checks, already O(count) validation → perf-neutral. Re-order WAL-append to AFTER admission gates.

### B4. mTLS is dead code (HIGH)
- **Evidence:** `cmq_tls.c:95-140` `tls_build_ssl_ctx` loads CA but never calls `SSL_CTX_set_verify`; verify-only call is in `cmq_tls_reload` (`:293-296`) which server never invokes. No `tls_ca`/`tls_verify_peer` config keys. `cmq_tls_set_verify`/`set_ca` are test-only.
- **Latent:** reload UAF — `SSL_CTX_free(old)` immediately at `:302` while `SSL*` from `SSL_new` holds no refcount → UAF if old SSL still in handshake.
- **Fix:** config keys → `tls_build_ssl_ctx` → `SSL_CTX_set_verify` + `SSL_CTX_set_cert_verify_callback` (custom CRL/OCSP). Reload via refcount/atomic swap (not free-then-replace).

### B5. F17 route TLS is dead code (MED-HIGH)
- **Evidence:** `cmq_route.c:174-192` `write_one`/`read_one` branch on `sess` param but ONLY call sites pass NULL (`:102`, `:156`). `cmq_route_tls.h:16-20` admits "socket BIO-wrap queued for v0.5.0" — never done. No `cmq_route_tls_sess_create` caller in `src/`. If wired naively, blocking `SSL_do_handshake` (`:15-32`) will hang the worker loop.
- **Fix:** nonblocking handshake via SSL `accept_state` machine + `SSL_ERROR_WANT_*` handling; bind to route's `eventfd` wakeup; integrate BIO with `write_one/read_one`'s existing path.

### B6. cmq_server_reload is racy / unsafe (HIGH, not unit-testable)
- **Evidence:** `cmq_server.c:7157-7190` frees `server->acl` / `server->blocklist` while workers read lock-free at `:2952` / `:4435`. `SSL_CTX_free(old)` at `:302` UAFs any in-flight `SSL*`.
- **Fix (structural, not testable in single-threaded harness):** atomic refcount/epoch pointer (`cmq_atomic_rc_t`) for acl/blocklist/ssl_ctx so workers hold a stable snapshot during read; reload bumps generation; old generation freed when last reader drops.
- **Regression gate:** TSAN/stress + ASAN smoke (pthread hammer + reload in loop). NOT a cmq_test.h RED test.

### B7. audit rotation is non-functional (MED)
- **Evidence:** `cmq_audit.c:82-94` `fopen` per event, `ftell` measures current line only (always small). `g_audit_path` is never set from config — no `cmq_audit_set_path` caller in `src/`.
- **Fix:** config key `audit_path` → `cmq_audit_set_path` at startup; rotation threshold + size-check (fseek-SEEK_END + ftell, compare to cap, rename → `.1` → open new).

### B8. Top-3 hot-path perf wins (est. cycle delta, bench to confirm)
1. **Sync WAL disk I/O** (`cmq_server.c:2940` → `cmq_filestore.c:493-538`): mutex + 2×flock + 2×fseeko/ftello + 2×fflush per publish. **~800K-1.5M cycles cold / 60-100K warm** (dominant). Fix: SPSC write-ahead ring (64 KiB chunks) + dedicated WAL thread; bounded + backpressure to preserve queue-full semantics. **Durability note:** today's contract is `fflush → kernel, no fsync` (cmq_filestore_sync only at destroy :7408); ring preserves this weaker contract; explicit fsync is a separate feature.
2. **QG dedup O(n²)** (`snapshot_deliver_targets` `cmq_server.c:1916-1931`): inner strcmp scan + 3 heap allocs per publish. **~40-200K cycles** (estimate) at 10K subs / 100 groups. Fix: FNV-1a hash of (subject, qgroup, account) → open-address slot → round-robin pick; stack buffers (bounded).
3. **Per-target copies + retry** (`worker_push_msg` `:925-940`, `deliver_via_worker` `:2079-2096`): extra memcpy per target, per-msg wakeup signal, 50µs nanosleep retry on queue-full. **~2-6K cycles/target** (soft estimate, mpool likely lower). Fix: batch same-worker targets into one mailbox entry; coalesce wakeup; per-worker freelist.

## C. Concessions (Round-3 evidence-driven)

- **low → high:** WAL replay is P0 (correctness above all features); F19 deferred to last.
- **artistry → ultrabrain:** subject_rl fix uses **atomic hash**, not mutex (mutex would add ~2.2M lock-acq/sec at 100K msg/s, replace race with throughput cliff).
- **high → ultrabrain:** async WAL ring preserves today's `fflush-only` durability (no fsync); if fsync desired, that's a separate feature.
- **high → low:** cycle deltas downgraded to estimates pending bench gate; WAL figure strongest, per-target softest.
- **ultrabrain → high:** reload-UAF caught by **structural refcount fix** + ASAN/TSAN stress, not unit test (race not deterministically reproducible in single-threaded harness).
- **artistry → all:** RED scenarios include security tests (replay_restores_messages, subject_rl.concurrent_no_bypass, batch_rl.acl_quota_rl_applied, tls.verify_peer_requires_client_cert, audit.rotation_after_cap, quota.connect_limit_enforced). F17 CPU gate made concrete (getrusage RUSAGE_THREAD on route worker loop, 10s/10K msg/s TLS-on/off, Δ≤5% wall time, handshake ≤5ms p50).
- **low → all:** P1 F19 split into P1a (skeleton + QoS0/1) and P1b (QoS2 + 5.0 props, deferred); P4+P5 sequenced (P4 after P5, both touch `tls_build_ssl_ctx`); per-P verification gates added to enumeration doc.

- Custom fsync policy (deferred; today's `fflush` contract preserved).
- TLS 1.3-only mode (current TLS 1.2/1.3 negotiation acceptable).
