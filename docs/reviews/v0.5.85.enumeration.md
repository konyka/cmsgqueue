# v0.5.85 — truncated retained-record recovery

## Scope

v0.5.85 hardens MQTT retained-file recovery against malformed
records whose declared payload length is unreasonable. The
loader previously trusted the declared length before allocating
the payload buffer. A damaged file could therefore cause an
unbounded allocation attempt or prevent later records from
being recovered.

## What v0.5.85 ships

### Production fix (`src/enterprise/cmq_mqtt_server.c`)

- Add `MQTT_MAX_RETAINED_PAYLOAD`, bounded by the existing
  `MQTT_MAX_PACKET` limit.
- Reject a retained record when its declared payload length
  exceeds that limit before calling `malloc`.
- Continue loading subsequent records after an oversized
  malformed header. This preserves valid retained messages
  after a damaged record and avoids a memory-amplification
  path during startup recovery.
- Keep the v0.5.84 read/write-path fix: the retain path stays
  disabled while records are loaded, preventing the loader
  from appending each recovered record back into the file.

### Defensive test (`tests/test_mqtt_retained_file.c`)

- **`mqtt_retained_file.truncated_record_does_not_poison_following`**:
  writes a record declaring a 1,000,000-byte payload without
  payload bytes, followed by a valid retained record. Calls
  `cmq_mqtt_set_retain_path`, verifies that no retained entry
  is created for the malformed topic, and verifies that the
  following valid topic and payload are recovered.

The malformed declaration is deliberately above the bounded
retained-payload limit. The test therefore exercises the
allocation guard without allocating attacker-controlled data
and completes quickly during startup recovery.

## Why this matters

Retained files are startup input. They can be truncated by a
crash, interrupted copy, or manual edit. Recovery must be
fail-safe: reject malformed data, avoid large allocations, and
continue to recover independent valid records. The regression
test locks in all three properties.

## Deferred (unchanged)

- TLS 1.3 mTLS via post-handshake auth. The TLS 1.2 cap
  remains in place; lifting it requires a test framework
  overhaul.
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
- Concurrent graceful-shutdown test (framework timing
  issue).
- TLS 1.3 session ticket resumption test (server does not
  issue tickets).
- Retain-file migration from the pre-v0.5.84 two-length
  format to the v0.5.84 single-length format. Existing
  deployments must clear old files before upgrading.
- Full binary-safe retained-file framing. The current text
  format remains newline-delimited and is intended for the
  existing retained-message payload contract.
