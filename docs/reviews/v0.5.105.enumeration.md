# v0.5.105 — `$JS` hash partitions (D4 follow-up)

## Scope
`cmq_stream` already has 1–16 partitions and
`append_key`. `cmq_js` always called `append` with
`nparts=1`. This increment wires partitions onto `$JS`.

## Design (performance-first, safety, reliability)

- `cmq_js_set_partitions(name, n)` only while empty
  (same as the stream). Default `n=1`.
- Persist `{dir}/js/{name}.parts` (`CMQP`) when
  `persist_dir` is set. Reopen loads `n` before replay.
- PUBLISH / WAL replay use `append_key(payload)` when
  `n>1`. Unpartitioned append is unchanged.
- `cmq_js_consume_part` uses `next_part`. Global
  consume / ack stay valid.
- Empty-stream / bad `n` fail closed.
