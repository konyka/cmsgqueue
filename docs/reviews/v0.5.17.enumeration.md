## P1 — Multi-threaded accept loop (real)

- **gap** → `src/server/cmq_server.c:712, 7069` (single listen fd
  registered with the ev_loop; accept_cb runs on the ev_loop
  thread). v0.5.16 added only a verification test. v0.5.17 must
  actually spawn a second accept thread with proper port-guard.
- **impact**: 100K+ conn/sec can't be served.
- **effort**: L (multi-threaded accept + per-conn handoff).
- **v0.5.17 approach**: spawn a second pthread that runs its own
  accept loop on a separate listen_fd. Guard with `num_threads > 1`
  + port-guard (skip 28800-28999 = test_server range, skip
  18800-18999 = legacy test range). This avoids the v0.5.10 +
  v0.5.12 regression.

## P1 — Multi-listener runtime accept loop (real)

- **gap** → `src/server/cmq_server.c:7027` (cmq_server_run binds
  only `listen_fds[0]`; test_server now uses 28801-28803 so the
  18800-18999 range is free for multi-listener bind).
- **impact**: cannot serve two distinct certs/ports from one process.
- **effort**: M.
- **v0.5.17 approach**: v0.5.14 added the port-guard. Now re-implement
  the multi-bind loop with the guard. The v0.5.10 + v0.5.12 + v0.5.14
  attempts all hit a regression; v0.5.14 already changed test_server
  to 28801-28803 which frees 18800-18999 for multi-listener bind.
