# v0.5.106 — `$JS` consume-part subject (D4 follow-up)

## Scope
`cmq_js_consume_part` exists, but REQUEST still calls
`cmq_js_consume`, which only parsed
`$JS.<name>.<consumer>`. Extra dots were malformed.
This increment parses `$JS.<name>.<consumer>.<part>`
(0–15) and dispatches to `consume_part`.

## Design (performance-first, safety, reliability)

- New `cmq_js_parse_part`. Last token is digits 0–15.
- `cmq_js_consume` tries `parse_cons`, then `parse_part`.
- `consume_part` accepts either two-token + part arg or
  the three-token subject.
- Two-token consume / ack unchanged.
- Part 16 / non-digits / extra dots fail closed.
- Server REQUEST already calls `cmq_js_consume`.
