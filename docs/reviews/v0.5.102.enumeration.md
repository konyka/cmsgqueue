# v0.5.102 — Disconnect spans (D1 follow-up)

## Scope
`KIND_CONNECT` is offered after CONNACK 0.
`CMQ_OP_DISCONNECT` only calls `client_force_closing`.
This increment adds `KIND_DISCONNECT` and offers one
on the graceful inbound path.

## Design (performance-first, safety, reliability)

- One disconnect span per inbound DISCONNECT opcode.
- Same 16-byte accept `trace_id`.
- Offer before `client_force_closing` so the id is still
  live.
- `otel == NULL`: no-op.
- Offer stays non-blocking; drop-newest unchanged.
