# v0.5.48 — Per-account concurrent limits

## Goal

Operators can cap concurrent connections, subscriptions, and
per-message payload per account. Default remains unlimited.

## Performance

- Unlimited: one atomic load + compare on CONNECT / SUBSCRIBE.
- PUBLISH: one extra integer compare when `account_max_payload`
  is 0 (the common case).
- No allocation, no extra manager lock on the inc path.

## Security

- CAS so the cap cannot be raced.
- Soft-delete / epoch undo is unchanged (prefer leak over theft).
- Payload cap cannot raise the global `max_payload_size`.
