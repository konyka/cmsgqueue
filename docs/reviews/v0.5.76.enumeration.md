# v0.5.76 — garbage tls_key rejected defensive test

## Scope

Sanity test: passing `tls_key=<path>` where the file contains
non-PEM data must fail at server startup. The v0.5.60 covers
the case where `tls_cert` is corrupt (different file from
`tls_key`); this test covers the case where `tls_key` itself
is corrupt.

## Test: `tls_e2e_handshake.garbage_tls_key_rejected`

1. Generate a valid self-signed cert + key pair (files in
   `TLS_DIR/cert.pem`, `TLS_DIR/key.pem`).
2. Create `TLS_DIR/garbage.key` containing "this is not a valid
   private key\n".
3. `cmq_server_create()` with `tls_cert=cert.pem`,
   `tls_key=garbage.key`, `tls_enabled=1`.
4. Assert return value is non-`CMQ_OK` and `srv == NULL`.

## What v0.5.76 ships

A regression test only. No production change.

## Why this test guards against regressions

If a future OpenSSL upgrade changes the failure path
(say, SSL_CTX_use_PrivateKey_file silently accepts garbage),
the test catches it at startup rather than at first handshake.
