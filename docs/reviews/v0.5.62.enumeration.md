# v0.5.62 — TCP RST during handshake defensive test

## Scope

The v0.5.50 `mid_handshake_disconnect` test covers a TLS client
that closes with `close()` (sending FIN). This v0.5.62 test
covers the more aggressive path: `SO_LINGER={1, 0}` + `close()`
which sends TCP RST instead of FIN. RST is the harder case
because the kernel actively rejects pending data, and the
peer (server) sees an error rather than a clean close.

## Test: `tls_e2e_handshake.mid_handshake_tcp_rst`

1. Spin up a TLS-enabled `cmq_server`.
2. Connect + send partial ClientHello.
3. Set `SO_LINGER={1, 0}` (force RST on close).
4. `close()` — sends RST instead of FIN.
5. Wait for server cleanup.
6. `cmq_server_stop` + `pthread_join` complete in bounded time.
