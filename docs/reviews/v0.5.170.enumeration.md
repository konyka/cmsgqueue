# v0.5.170 — wire WS permessage-deflate on upgrade

## Scope
v0.5.22 shipped `cmq_ws_parse_extensions` / deflate /
inflate. The live upgrade path never negotiated, and
send/recv never compressed, so clients that offered
RFC 7692 still paid full-size frames.

## Design (performance-first, safety, reliability)

- `cmq_ws_negotiate_deflate`: 1 = accept and fill the
  response line; 0 / omitted / empty keeps off; bad
  tokens fail closed.
- Upgrade calls negotiate before the 101. Unsupported
  parameters abort the handshake.
- Outbound BINARY frames deflate and set RSV1 when
  negotiated. Control frames stay uncompressed.
- Inbound data frames use `parse_ex(allow_rsv1)`.
  RSV1 on the first fragment inflates the assembled
  message; RSV1 on CONTINUATION fail-closes.
- Existing cache of uncompressed WS clients is unchanged.
