# v0.5.171 — verify CHECKSUM on REQUEST

## Scope
F3 verified `CMQ_FLAG_CHECKSUM` only in
`handle_publish`. The parser accepts the bit on
REQUEST, so the trailing CRC32C was treated as
body bytes — the same silent interop class as
COMPRESSED before v0.5.98.

RESPONSE / BATCH stay as later cuts.

## Design (performance-first, safety, reliability)

- `cmq_checksum_consume`: 0 / omitted / empty flags
  keep `*len`. CHECKSUM verifies the trailing
  little-endian CRC32C and subtracts 4. Short /
  NULL / mismatch fail closed and do not rewrite
  `*len`.
- `handle_request` consumes after inflate, before
  inbox / subject parse.
- `handle_publish` uses the same helper so there is
  one verify path.
