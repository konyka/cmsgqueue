# v0.5.124 — reload F14 quota and N1 subject rate limit

## Scope
Create builds `cmq_quota` and `cmq_subject_rl` from
`max_msgs_per_sec_per_account`, `max_bytes_per_sec_per_account`,
`max_connections_per_account`, and
`max_msgs_per_sec_per_subject`. Reload never touched those
objects, so changing a cap required a restart (quota.md
Limitation).

## Design (performance-first, safety, reliability)

- In-place `max_*` stores. No pointer swap, so PUBLISH
  cannot UAF the table it is walking.
- 0 / omitted keeps the current cap.
- Create-without-quota can gain an object when a cap is set.
- Out-of-range values fail closed before any store.
