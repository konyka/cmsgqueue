# v0.5.107 — `$JS` default partitions (D4 follow-up)

## Scope
`cmq_js_set_partitions` was library-only. The server never
called it, and config had no `js_partitions`. New streams
stayed `nparts=1` unless a `.parts` file already existed.
This increment adds `cmq_js_set_default_partitions` and
wires `js_partitions` (2–16) at `cmq_js_create`.

## Design (performance-first, safety, reliability)

- `def_parts` on `cmq_js` (init 1).
- Apply after create, before history replay, only when no
  `.parts` file was loaded.
- Existing `{name}.parts` wins over the default.
- Config `js_partitions` is 0–16; 0 and 1 mean unpartitioned.
- 0 / 17 / NULL reject. Server applies only when n>1.
