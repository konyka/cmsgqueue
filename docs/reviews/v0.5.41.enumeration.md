## This-round P1 — F2 wire compression is dead on the parser

- **gap** → `src/proto/cmq_parser.c:257-265` still sets
  `pending_error` for **every** `CMQ_FLAG_COMPRESSED` frame, including
  `CMQ_OP_BATCH`. `handle_batch` (`src/server/cmq_server.c:4210-4236`)
  already decompresses zstd, and INFO advertises `"compression":"zstd"`.
  Compressed BATCH never reaches the handler.
- **gap** → `handle_batch` sizes the dest buffer with
  `cmq_compress_bound(frame->payload_len)`. On the wire `payload_len`
  is the **compressed** size. `ZSTD_compressBound(compressed_len)` is
  ~1.1× that length, not the original size. A 4 KiB payload that
  compresses to ~40 B cannot decompress into a ~50 B buffer.
- **impact**: advertised F2 is a no-op; clients that honor INFO and
  set the flag are disconnected. Security: the unused path also
  lacks a correct bomb bound (content-size + 16 MiB).
- **effort**: S/M. Verification: parser accepts COMPRESSED+BATCH,
  still rejects COMPRESSED+PUBLISH; e2e compressed batch delivers
  a high-ratio payload.
