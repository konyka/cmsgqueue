# v0.5.45 — Filestore rotation / compact

## Scope
R5 from v0.5.41: `cmq_filestore` is append-only. There is no
snapshot or truncate, so a long-lived broker's `.data` / `.idx`
grow without bound (`docs/features/persistence.md`). Kafka-style
key compaction remains D6 / v0.6+.

Remaining P2 after this round: R6 MQTT will/sessions, R7
connz/subz/routez.

## Design (performance-first, safety, reliability)

### Explicit compact

`cmq_filestore_compact(fs, retain)` keeps the newest `retain`
records, rewrites them as seq 1..retain into temp files, fsyncs,
then `rename`s over the live pair. `retain == 0` truncates both
files in place (no rewrite). If `retain >= last_seq`, return 0
with no I/O.

### Size-cap rotate

`cmq_filestore_set_rotate_bytes(cap)` (0 = off, default). After a
successful sync append, if `data_end_off >= cap`, archive
`prefix.data` / `.idx` to `.1` (one generation) and open empty
live files. The append that crossed the cap is in `.1`, not lost
from disk.

Hot path when cap is 0: one integer compare (false).

### Safety

- Compact / rotate run under the same mutex + `flock` as append.
- Temp files are fsync'd before rename.
- CRC is re-checked while copying; a bad record fails closed
  (live files untouched).
- Path prefix rules unchanged (no new traversal).
