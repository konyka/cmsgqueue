# v0.5.45 — End-to-end TLS handshake through cmq_server_run

## Scope

v0.5.27 wired the OpenSSL callbacks into the cmq_tls session cache.
v0.5.28 added a real end-to-end handshake test, but it bypasses
`cmq_server` entirely — it builds a synthetic socketpair and drives
the handshake against a freestanding SSL_CTX. v0.5.33 wired the
per-listener TLS slot lookup into `accept_cb`. v0.5.45 closes the
loop: a test that starts `cmq_server_run` with TLS enabled, opens a
real TCP connection, completes a real `SSL_connect` handshake, and
verifies the server accepted the connection. Then a second test runs
the same scenario against `port+1` to verify v0.5.33's slot lookup
maps the listen fd to the correct per-listener SSL_CTX.

## Bug found during exploration

While writing the design plan, a real production bug surfaced in
`client_tls_handshake` (cmq_server.c:6395–6412):

```c
int rc = cmq_tls_handshake(tls);
if (rc != 0) {
    cmq_tls_session_destroy(tls);
    return -1;
}
client->tls = tls;
return 0;
```

`cmq_tls_handshake` returns:
- `1` = success (handshake complete)
- `0` = WANT_READ / WANT_WRITE (try again)
- `-1` = fatal error

The current `if (rc != 0)` matches **both** success and error,
destroys the session, and returns `-1`. Net effect:

| `cmq_tls_handshake` rc | current behavior | correct behavior |
|---|---|---|
| `1` (done) | destroy session, return -1 (reject!) | set client->tls, return 0 |
| `0` (WANT_*) | set client->tls, return 0 | set client->tls, return 0 |
| `-1` (fatal) | destroy session, return -1 | destroy session, return -1 |

So today, **a TLS handshake that completes synchronously on accept
silently kills the connection**, and a TLS handshake that needs
multiple round-trips is accepted but never resumed — the
`client_read_cb` path reads via `cmq_tls_read` which returns -1
when `handshake_done` is false.

v0.5.45 fixes this bug and adds a regression test.

## Design

### Fix 1: `client_tls_handshake` return-value handling

```c
int rc = cmq_tls_handshake(tls);
if (rc < 0) {
    cmq_tls_session_destroy(tls);
    return -1;
}
/* rc == 0 (WANT_READ/WANT_WRITE) or rc == 1 (success) — both keep
 * the session alive so client_read_cb can resume the handshake
 * when EV_READ fires. */
client->tls = tls;
return 0;
```

### Fix 2: handshake resume in `client_read_cb`

When `c->tls && !c->tls->handshake_done`, the client read callback
must drive the handshake to completion before falling through to
the normal protocol parser. Otherwise bytes read via
`client_sock_read` (which delegates to `cmq_tls_read`) would be
discarded because `cmq_tls_read` refuses to read until the
handshake is done.

```c
if (events & CMQ_EV_READ && c->tls && !cmq_tls_handshake_done(c->tls)) {
    int hrc = cmq_tls_handshake(c->tls);
    if (hrc < 0) { client_teardown(c); return; }
    /* rc == 0 → still pending; bail out without reading application data. */
    if (hrc == 0) return;
    /* rc == 1 → handshake complete; fall through to normal read. */
}
```

The same resume logic applies on EV_WRITE because OpenSSL's state
machine needs to write the next flight when WANT_WRITE was
returned. Symmetric handling in the write path (`client_flush_write`
or wherever EV_WRITE is dispatched) — at minimum, calling
`cmq_tls_handshake` on EV_WRITE.

To avoid plumbing `c->tls->handshake_done` everywhere, expose a
small accessor `cmq_tls_handshake_done(c->tls)` (or use the
existing internal field through the existing
`cmq_tls_session_t` abstraction — see `cmq_tls.h`).

### Test 1: `tests/test_tls_e2e_handshake.c` — single-listener

1. Generate a self-signed cert+key under `/tmp/cmq-test-v0545`.
2. Configure `cmq_config_t` with `tls_enabled=1`,
   `tls_cert=/tmp/.../cert.pem`, `tls_key=/tmp/.../key.pem`, bind
   to a free port (e.g. 25510).
3. `pthread_create` a thread running `cmq_server_run(srv)`.
4. Wait for `srv->listen_fds[0] >= 0`.
5. Open a TCP socket to 127.0.0.1:25510.
6. Build a TLS client `SSL_CTX` (TLS_client_method), load the same
   cert as a CA, build `SSL*`, `SSL_set_fd`, `SSL_set_connect_state`,
   then drive `SSL_do_handshake` on a dedicated thread (mirroring the
   v0.5.28 select() loop pattern).
7. Assert handshake completes (rc==1 from `SSL_do_handshake`).
8. Write a small CMQ-like frame (or just send "PING\r\n") and read
   the response (or the close).
9. `cmq_server_stop`, `pthread_join`, `cmq_server_destroy`.

### Test 2: multi-listener (slot 0 + slot 1)

1. Generate two distinct certs (`cert0.pem/key0.pem` for CN=slot0,
   `cert1.pem/key1.pem` for CN=slot1).
2. Configure two listeners: `tls_cert=cert0.pem`, `tls_key=key0.pem`
   for slot 0, and `listeners[1].tls_cert=cert1.pem`,
   `listeners[1].tls_key=key1.pem` for slot 1, `listener_count=2`.
3. Spin `cmq_server_run` in a background thread.
4. Connect to port 25511 (slot 0's port) with a client that trusts
   cert0 → expect handshake success.
5. Connect to port 25512 (slot 1's port = port+1) with a client that
   trusts cert1 → expect handshake success.
6. Cross-check: connect to slot 1's port but verify against cert0 →
   expect handshake failure (SSL_VERIFY_FAIL).

Test 2 directly verifies v0.5.33's `srv_find_tls_slot` is the one
used by `client_tls_handshake` in production, not just in a unit
test.

## Safety

- Backwards-compatible: clients without `tls_enabled` go through
  `client_tls_handshake` which returns 0 immediately when
  `srv->tls_config_slots[0]` is NULL. Existing plaintext behavior
  unchanged.
- The fix only changes the `rc != 0` branch to `rc < 0`. The
  pending-state (`rc == 0`) path was already correct. So the only
  behavioral change is "rc == 1 no longer kills the session".
- `cmq_tls_session_destroy` is still called on real errors.
- The new accessor `cmq_tls_handshake_done` is a read-only
  predicate; no new state.

## Performance

- Handshake resume on EV_READ adds 1 `SSL_do_handshake` call per
  wakeup until `handshake_done` flips. Each call is cheap (state
  machine check, no I/O when complete). Negligible overhead.
- No changes to the existing hot path; EV_WRITE branch only
  re-enters the handshake when `!handshake_done`.

## Test framework

- Pure C, uses `cmq_test.h` macros (TEST/TEST_MAIN).
- Cert gen: `openssl req -x509 -newkey rsa:2048` in a `system()`
  call (same pattern as v0.5.32 / p5_listener).
- Drive the TLS handshake on a dedicated thread (each side of the
  handshake needs its own select()/SSL_do_handshake loop, otherwise
  OpenSSL state machines deadlock — v0.5.28 learned this).
- Cleanup: `rm -rf /tmp/cmq-test-v0545` in a final teardown.

## Risk

- v0.5.45 fixes a production bug; tests that previously relied on
  the broken behavior would break. None of the existing tests
  exercise TLS through `cmq_server_run`, so the blast radius is
  zero.
- The fix is small and surgical (2-line change in
  `client_tls_handshake`, plus a guarded re-entry block in
  `client_read_cb`).
- No benchmark regression expected — handshake resume is O(1) per
  wakeup until done.

## Deferred to v0.5.46+

- TLS session resumption (gen_session_id callback installed but the
  resume path is not exercised end-to-end — `session_reused_on_reconnect`
  test was a stub since v0.5.29).
- TLS write-path handshake resume (mirror the read-path fix on the
  EV_WRITE branch). v0.5.45 only adds the read-path resume because
  the client's first flight is a write that triggers WANT_WRITE on
  the server. The server's EV_WRITE branch may also need a resume
  hook, but the simpler fix is to drive the handshake on every
  wakeup regardless of READ/WRITE direction.
