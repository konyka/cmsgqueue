# v0.5.22 — WS permessage-deflate (RFC 7692)

## Scope
Implement WebSocket permessage-deflate compression (RFC 7692) end-to-end at the
WS layer. The placeholder test in v0.5.15 (`tests/test_ws_deflate.c`) covers the
no-extension default; v0.5.22 covers actual compression when the client
negotiates the extension.

This is the highest-value deferred item from v0.5.21's enumeration:
WS text frames (JSON, chat, pub/sub notifications) typically achieve 60–80 %
compression. Without deflate, every publish to a WS subscriber pays full
network + serialization cost.

## Design (performance-first, safety, reliability)

### Architecture
Add a per-connection `z_stream` (zlib) for both inflate (server-decompress
incoming) and deflate (server-compress outgoing). Stream state lives on the
existing `cmq_ws_client_t` struct.

Key parameters per RFC 7692 §7.1:
- `windowBits = 15` (zlib's max, matches permessage-deflate defaults).
- `memLevel = 8` (zlib's default; balances RAM vs ratio).
- `level = Z_DEFAULT_COMPRESSION` (6) — best speed/ratio trade-off per zlib docs.
- Flush mode for chunked writes: `Z_SYNC_FLUSH` per "compressed message" boundary.

### Negotiation
1. Parse `Sec-WebSocket-Extensions: permessage-deflate; ...` from the upgrade request.
2. Reply with `Sec-WebSocket-Extensions: permessage-deflate; server_no_context_takeover; client_no_context_takeover`.
3. Veto with HTTP 400 if the client requests an unsupported parameter.

`server_no_context_takeover` and `client_no_context_takeover` are both enabled
so each connection gets its own inflater/deflater (no per-connection state
across messages). This trades ~256 KB per connection for state isolation —
matches the multi-tenant threat model and avoids cross-tenant information
leaks via shared zlib dictionary.

### Per-frame handling (server-side)
**Incoming (client→server):**
- After `cmq_ws_frame_parse`, if `cmq_ws_client_t.deflate_enabled` is set and
  the frame is data (BINARY or TEXT, not control), inflate the payload.
- Strip the trailing `0x00 0x00 0xFF 0xFF` (RFC 7692 §7.2.2) before inflate.
- Replace the parsed payload pointer with the inflated buffer; call the
  user callback with the inflated bytes.

**Outgoing (server→client):**
- Before `cmq_ws_send`, if deflate is enabled and it's a data frame, deflate
  the payload into a temp buffer, append `0x00 0x00 0xFF 0xFF`, then send
  with RSV1 bit set on the frame header.
- Per RFC 7692 §7.2.1.1: do NOT set RSV1 on the final fragment of a
  fragmented message — only on intermediate fragments. v0.5.22 only emits
  unfragmented frames (FIN=1), so the question reduces to: always set RSV1
  on the single frame. (Future fragmented-message support will need to clear
  RSV1 on the final fragment.)

### Safety
- Hard cap incoming deflated payload at the existing `16 MB` ceiling in
  `cmq_ws_frame_parse` — already enforced; no further cap needed because the
  decompressed buffer inherits the same cap.
- Set `inflateInit2` with `windowBits = -15` (raw deflate, no zlib header).
- Always call `inflateEnd` / `deflateEnd` on connection teardown.
- On `Z_DATA_ERROR` or `Z_MEM_ERROR`, force-close the connection rather than
  feed garbage to the upper layer.
- Bounded allocation: keep a `cmq_ws_client_t.deflate_inflate_buf` sized to
  `CMQ_WS_DEFLATE_BUF_MAX` (64 KB), grow on demand but cap at `16 MB`.

### Reliability
- Per-message deflation boundary uses `Z_SYNC_FLUSH` ⇒ receiver gets a clean
  sync point, no prefix ambiguity.
- Errors propagate via return code from `cmq_ws_send` / `cmq_ws_frame_parse`;
  the caller (server accept loop) tears down on `-1`.
- Concurrency: zlib streams are per-connection and never shared, so no locks
  needed on the stream itself.

### API additions
```c
/* Returns 1 if deflate extension negotiated, 0 otherwise, -1 on parse error. */
int cmq_ws_parse_extensions(const char *req, size_t req_len);

/* Build Sec-WebSocket-Extensions response line for permessage-deflate. */
int cmq_ws_build_extensions_response(char *out, size_t out_len);

/* Compress one message. Writes deflated bytes to out (with trailing 0x00 0x00 0xFF 0xFF).
   Returns bytes written or -1 on error. */
int cmq_ws_deflate_message(const uint8_t *in, size_t in_len,
                            uint8_t *out, size_t out_cap);

/* Decompress one message. Writes inflated bytes to out.
   Returns bytes written or -1 on error. */
int cmq_ws_inflate_message(const uint8_t *in, size_t in_len,
                            uint8_t *out, size_t out_cap);
```
