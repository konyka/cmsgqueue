Parallel-safe examples:
- Track A (filestore) + Track B (TLS) are entirely disjoint files.
- Track C (MQTT) + Track D (perf) are disjoint modules.
- Track B (multi-listener) and Track A (async WAL) both modify `cmq_server.c` — sequence: B finishes first since async WAL rewrites the write path.

## 4. Per-P-item Micro-Plans

### P1 async WAL ring (SPSC + worker thread)
- **Goal**: `src/store/cmq_filestore.c:436` — replace inline flock+fflush with SPSC ring + dedicated WAL worker thread; publisher returns after one memcpy.
- **Pre**: nothing (v0.5.1 P2 cached offsets is foundation).
- **Implementation**: 64 KiB chunks; `cmq_filestore_append` becomes memcpy + eventfd wakeup; worker drains in batches; bounded backpressure; `cmq_filestore_sync` triggers explicit drain+fflush. ~280 LOC.
- **RED**: `tests/test_wal_async.c` — burst 10K appends, assert `stat_messages_dropped == 0` and `last_seq == N`; shutdown drain test.
- **Docs/ADR**: ADR 0016b (update); `docs/features/persistence.md` "Async WAL ring" section.
- **Atomic**: `feat(P1): SPSC async WAL ring with dedicated worker thread`.

### P3 fsync policy option
- **Goal**: `src/store/cmq_filestore.c:503` — add `cmq_filestore_set_sync_interval`; periodic `fdatasync` on the data fd when interval elapses.
- **Pre**: P1 async ring (so we don't fsync per message).
- **Implementation**: ~30 LOC. Keep `cmq_filestore_sync` as the explicit knob.
- **RED**: `tests/test_wal_fsync.c` — small interval, kill -9 restart, replay recovers.
- **Docs/ADR**: `docs/features/persistence.md`.
- **Atomic**: `feat(P3): optional periodic fsync policy`.

### P4 STATS counter accuracy under replay
- **Goal**: `src/server/cmq_server.c:2940` — distinguish replay from live. Add `stat_messages_replayed`.
- **Pre**: P0 fd=-1 sentinel already in place.
- **Implementation**: increment a separate counter when `c->fd == -1`; do not increment `stat_messages_in` for replays. ~10 LOC.
- **RED**: `tests/test_wal_replay.c::stats_separate_replay` — restart with persisted publishes, assert `stat_messages_in == 0` and `stat_messages_replayed == N`.
- **Docs**: `docs/features/persistence.md`.
- **Atomic**: `fix(P4): separate stat for replayed messages`.

### P2 multi-listener: slots[1..3]
- **Goal**: `src/server/cmq_server.h:165` CMQ_MAX_LISTENERS=4 — currently only slot[0] populated. Wire slots[1..3] via new config keys.
- **Pre**: v0.5.1 P5 refcounted SSL_CTX already in place.
- **Implementation**: `cmq_config_t.listeners[]` array (host+port+cert+key+ca+verify per slot). `cmq_server_create` builds slots[0..N-1]. `cmq_server_run` listens on all of them. ~200 LOC.
- **RED**: `tests/test_p5_listen.c::two_listeners_distinct_ctx` — start server with 2 listener configs, both accept a TLS handshake with their own cert.
- **Docs/ADR**: `docs/adr/0010-per-listener-ssl-ctx.md` (extend).
- **Atomic**: `feat(P2): wire listener slots[1..3]`.

### P2 custom CRL/OCSP for mTLS
- **Goal**: `src/enterprise/cmq_tls.c:136` — register `SSL_CTX_set_cert_verify_callback`; check CRL path or OCSP responder.
- **Pre**: v0.5.1 P1 mTLS wiring.
- **Implementation**: `cmq_tls_set_crl(cfg, path)`, `cmq_tls_set_ocsp(cfg, url)`; verify_cb loads CRL or queries OCSP. ~120 LOC.
- **RED**: `tests/test_mtls_api.c::crl_revoked_cert_rejected`.

## 6. Risk Register

| Item | Risk | Mitigation |
|---|---|---|
| P1 async ring | Ring-full backpressure can stall publisher if worker falls behind | Bounded chunks + drop counter; explicit `cmq_filestore_sync` still synchronous for durability |
| P1 MQTT bridge | Inserting a sub-ref for every PUBLISH topic explodes sublist | Coalesce identical topics in a small LRU; per-publisher dedup |
| P1 replay parallel | Workers racing on `srv->accounts` mutex | Each partition owns a disjoint account set (hash by account name) |
| P2 multi-listener | Two SSL_CTX reloads racing | Per-listener `cmq_rch` handle; reload uses same swap pattern as v0.5.1 P1 |
| P2 CRL/OCSP | Revoked cert on offline CRL hangs handshake | CRL loaded eagerly at startup; OCSP uses short timeout |
| P4 STATS under replay | Operators expect `messages_in` to reflect live traffic only | Document `stat_messages_replayed` separately; keep `messages_in` for live only |

## 9. Stop Conditions

Stop the affected track and ask the lead before continuing if:
- Required RED test fails for a reason other than the documented defect.
- Production code proposed before RED test lands and demonstrates expected failure.
- Default ctest regresses or discovery count drops below 63.
- TSAN reports new race in unrelated code.
- ASAN or UBSAN reports error on changed path.
- Bench regresses > 10%, or 5-10% without attributable measurement noise.
- P1 async ring cannot preserve ordered batched fflush, bounded backpressure, or destroy-drain behavior.
- Multi-listener cannot keep two listener reloads independent (one reload affects the other).
- MQTT QoS2 retransmit logic not idempotent.
- WAL replay parallel partition produces non-deterministic state.
- Any proposed change creates a 14th P-item; submit to a new adversarial round.
