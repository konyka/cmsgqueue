# v0.5.52 — Account outstanding-byte cap

## Scope
D8 left a per-message `max_payload` but no live memory budget.
`bytes_in` is cumulative traffic, never decremented.

This increment adds `bytes_live` + `max_bytes_live`. Credit for
an in-flight publish, debit when that publish returns.

D1–D6 stay deferred.

## Design (performance-first, safety, reliability)

- `max_bytes_live == 0`: no tracking (cached on the client at
  CONNECT; publish is one integer compare).
- Credit is a CAS: reject `-2` if `cur + n > max` or overflow.
- Debit is saturating; stale epoch / clear_gen prefers leak
  over theft (same as conn/sub).
- Hold starts after export / quota / rewrite, so a reject does
  not consume budget. Drop on every return after the hold.
- Config: `account_max_bytes_live`. Separate setter so
  `set_limits` stays ABI-stable.

This bounds concurrent in-flight ingress, not subscriber
write-buffer copies (that needs per-target debit).
