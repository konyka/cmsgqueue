# v0.5.52 — concurrent TLS handshakes defensive test

## Scope

v0.5.45 added the per-client handshake-resume path. v0.5.50
and v0.5.51 added defensive tests for single-client error
paths (mid-handshake disconnect, garbage TLS record).
v0.5.52 adds a concurrency test: 8 simultaneous TLS
handshakes against a `num_threads=4` server.

The v0.5.45 read-path resume is per-client (each client has
its own `cmq_tls_session_t` with its own SSL* and event loop
context). The test verifies that concurrent threads driving
concurrent handshakes don't cross-contaminate state.

## Test: `tls_e2e_handshake.concurrent_handshakes`

```c
enum { N_CLIENTS = 8 };
pthread_t c_tids[N_CLIENTS];
v0552_arg_t args[N_CLIENTS];
for (int i = 0; i < N_CLIENTS; i++) {
    args[i].port = 25524;
    pthread_create(&c_tids[i], NULL, v0552_client_thread, &args[i]);
}
for (int i = 0; i < N_CLIENTS; i++) {
    pthread_join(c_tids[i], NULL);
    ASSERT_EQ(args[i].rc, 1);  /* each handshake must succeed */
}
```

Each `v0552_client_thread` opens a TCP socket to port 25524
and runs a full TLS handshake via `drive_handshake`. The
test asserts all 8 handshakes succeed.
