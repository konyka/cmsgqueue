# v0.5.112 — MQTT bridge outbound PUBLISH (F6 follow-up)

## Scope
`srv->mqtt_bridge` connected but never forwarded CMQ
PUBLISH. There was no `cmq_mqtt_bridge_publish`, no
config mapping, and handle_publish did not call the
bridge. The documented contract is “forward matching
subjects to the upstream broker.”

## Design (performance-first, safety, reliability)

- `cmq_mqtt_bridge_publish`: exact subject match, encode
  MQTT PUBLISH, write. 1 hit / 0 miss / -1 fail.
- QoS>0 uses a wrapping non-zero packet id.
- Write failure disconnects the live fd.
- Server hook after rewrite; skip routes, replay (`fd==-1`),
  and `mqtt_bridge*` accounts (no loop).
- Repeatable `mqtt_bridge_map=subject,topic[,qos]` (max 8).
  CMQ subject rejects `/`. Applied after a successful connect.
