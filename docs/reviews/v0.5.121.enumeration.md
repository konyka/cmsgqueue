# v0.5.121 — reload persist_sync_interval_ms

## Scope
Create calls `cmq_filestore_set_sync_interval` from
`persist_sync_interval_ms`. `cmq_server_reload` only logged
`persist_dir` and never pushed a new interval, so changing
the fsync policy required a restart.

## Design (performance-first, safety, reliability)

- `cmq_filestore_reload_sync` copies a non-zero fresh
  interval onto `live_ms` and the open filestore.
- 0 / omitted keeps the current policy (cannot disable
  via a file that leaves the key out).
- Values above 86400000 fail closed.
- `fs` may be NULL when WAL is off; the live scalar still
  updates so a later persist_dir open is not required here.
