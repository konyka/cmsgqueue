# v0.5.57 — MQTT outbound QoS 2

## Scope
Inbound QoS 2 (PUBREC / PUBREL / PUBCOMP) already exists.
v0.5.54 added a 16-slot outbound window but `offer` only
accepts QoS 1 and SUBSCRIBE still grants at most 1.

This increment grants QoS 2 on SUBSCRIBE, encodes outbound
`PUBLISH` as `0x34`, advances on `PUBREC` with `PUBREL`
(`0x62`), and frees the slot on `PUBCOMP`.

D1–D3, D4 KV, and D5 transactions stay deferred.

## Design (performance-first, safety, reliability)

- Same 16 inline slots. One extra `phase` byte:
  0 = wait PUBACK / PUBREC, 1 = wait PUBCOMP.
- `offer` accepts qos 1 or 2. qos 0 / 3 rejected.
- Window full still skips that dest (publisher not blocked).
- `ack` on a QoS 2 slot before `rec` fails (wrong packet).
- `rec` on a QoS 1 slot fails.
- Packet id never 0. Payload cap 1024 unchanged (`-3`).
