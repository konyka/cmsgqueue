# CMSGQueue v0.5.1 — TDD Workflow + Doc Template Plan

**Role.** TDD + docs workflow designer (workflow only — no feature design).
**Scope source.** `docs/reviews/v0.5.1.enumeration.md` (P1–P8), verified against
HEAD `cbc5cc9`. Test infra: `tests/cmq_test.h` (self-registering `TEST(suite, name)`,
`ASSERT*`, `TEST_MAIN()`), CTest glob over `test_*.c`, `cmq_test.h` header.

---

## 0. Shared TDD workflow (applies to every feature)

1. **Doc-first.** Draft `docs/features/<feature>.md` sections `## Design` and
   `## Tests` BEFORE code — the `## Tests` section lists the exact test names
   that must exist. This is the contract.
2. **RED.** Add `tests/test_<feature>.c` with the named tests. Run the binary
   directly first (`./build/tests/test_x`) — confirm each fails for the *expected*
   reason (assertion, not compile/link).
3. **GREEN.** Implement minimal code. Re-run the single test binary until green.
4. **REFACTOR.** Rename/dedupe only; keep tests green.
5. **Full gate.** `cd build && ctest --output-on-failure -j$(nproc)`.
6. **Hardening/ASAN.** Rebuild with `-DCMQ_ENABLE_HARDENING=ON` and
   `-DCMQ_ENABLE_ASAN=ON -DCMQ_ENABLE_UBSAN=ON`, re-run the new tests.
7. **Doc completion.** Fill `## Verification gates` (measured counts + the exact
   command), `## Performance`, `## Security`, `## Limitations`, `## See also`
   (reference the enumeration P#).
8. **Atomic commit** per feature, repo-style message (`feat(server): ...`,
   `test(...): ...`, `docs: ...`).

Order the squad by effort, quick wins first: P7 → P2 → P3 → P5 → P6 → P4 → P8 → P1.
Nothing depends on the full suite being red; each feature lands on green `main`.

## Doc template standardization tweaks

Audit: 20/23 `docs/features/*.md` follow a 9-section template. Deviations:
`flag-rejection.md` (`## Verification Gates`, `## See Also`, extra `## API`);
`tls-hardening.md`, `test-stress-flake-fix.md`, `mqtt-server-stub.md`,
`sublist-persist.md` use `## Status`/`## Changes`/`## Verification`. Duplicate
F-numbers across files (F1, F8, F11, F12, F15). No doc states the run command.

**Canonical template** (H1 = `# <F/P>: <Title>`):

```
## Motivation
## Design
## Files touched
## Tests            # exact test names + counts, e.g. "4/4 quota tests pass"
## Verification gates  # measured counts + the exact command used
## Performance
## Security
## Limitations
## See also         # reference enumeration P# + sibling feature docs
```

Tweaks:
1. **Exact casing** — `## Verification gates` and `## See also` (match 20/23);
   normalize `flag-rejection.md`.
2. **Optional `## Status`** — allowed immediately after the H1 for stub/follow-up
   features (kept by `sublist-persist.md` / `mqtt-server-stub.md`), but the body
   must still follow the 9 sections.
3. **Optional `## API`** — only when a new public surface is added; placed after
   Design (per `flag-rejection.md` precedent).
4. **Verification gates must state the command** — e.g. `cd build && ctest
   --output-on-failure -j$(nproc)` plus the direct binary
   (`./build/tests/test_x`), not just a count.
5. **De-stub renames** — on implementation, rename the file and update all
   cross-refs; no `(STUB)` titles remain at release.
6. **Disambiguate numbering** — new v0.5.1 docs use the enumeration P-numbers
   (P1–P8) or fresh sequential F-numbers; never re-use an F-number already claimed
   by an existing doc.
7. **Doc-first contract** — `## Design` + `## Tests` are written before code;
   `## Verification gates`/`## Performance`/`## Security`/`## Limitations` are
   filled with measured data after green.
