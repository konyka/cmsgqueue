# v0.5.82 — JWKS refresh (D3 phase 9)

## Scope
`jwks_url` is fetched once at create. IdP key rotation
needs a periodic re-GET. This increment adds
`jwks_refresh_sec` and a ping-pong cache so CONNECT
sees the latest document without a stale pointer.

## Design (performance-first, safety, reliability)

- `jwks_refresh_sec` 0: one GET at create (existing path).
- Interval 5–86400 seconds. Failed GET keeps the old cache.
- Ping-pong slots: install into the idle slot, then flip
  the index. CONNECT reads the live slot (no mutex).
- Same 200 ms / 4 KiB GET (HTTP or HTTPS).
- Refresh without `jwks_url` is rejected.
