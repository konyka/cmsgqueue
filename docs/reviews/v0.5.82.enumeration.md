# v0.5.82 — ALPN end-to-end defensive test + production fix

## Scope

v0.5.82 closes one P2 gap and adds a defensive test:

1. **P2: ALPN not applied on initial load** — `cmq_tls_set_alpn`
   stores the ALPN list on the `cmq_tls_config_t`, but the initial
   `cmq_tls_load` → `tls_build_ssl_ctx` path in
   `src/enterprise/cmq_tls.c` does NOT call
   `SSL_CTX_set_alpn_protos`. ALPN is only applied inside
   `cmq_tls_reload`. The user calls `cmq_tls_set_alpn` then
   `cmq_tls_load`; the cert chain is loaded, the server starts, but
   the server's SSL_CTX has no ALPN. Clients that send an ALPN
   extension in the ClientHello receive no ALPN response. This is a
   silent functional regression for users who configure ALPN for
   HTTP/2 / NATS-WebSocket handoff.

2. **P2: real-listener ALPN negotiation defensive test** — covers
   the production code path through `cmq_server_create` →
   `cmq_tls_load` → accept → TLS handshake. Test sets ALPN on
   the server, runs an OpenSSL client with `SSL_set_alpn_protos`,
   and asserts the negotiated protocol is what the server offered.

## What v0.5.82 ships

- **Production fix** (`src/enterprise/cmq_tls.c::tls_build_ssl_ctx`):
  apply `SSL_CTX_set_alpn_protos` from `cfg->alpn_data` /
  `cfg->alpn_len` when `alpn_len > 0`, mirroring the code already
  in `cmq_tls_reload`. Without this, the ALPN extension is
  silently missing on the initial server startup.
- **Defensive test**
  (`tests/test_tls_e2e_handshake.c::alpn_negotiated_on_real_listener`):
  - Spins up `cmq_server` with TLS enabled on port 25579.
  - Configures the server's `tls_config_slots[0]` with
    `cmq_tls_set_alpn("h2,nats")` BEFORE `cmq_tls_load`.
  - Runs an OpenSSL client with `SSL_set1_protocols_protos` of
    `["nats","spdy/3.1"]` (no "h2" in the client's preference so
    the server's "nats" wins).
  - Asserts the handshake completes (rc == 1).
  - Reads `SSL_get0_alpn_selected` and asserts the negotiated
    protocol string is "nats" (length and bytes match).
- **Bench**: unchanged.
- **CHANGELOG + tag + push**.

## Test design

- Use port 25579 (next available after 25577 used in v0.5.76).
- Use `drive_handshake`-like pattern: dedicated thread drives
  `SSL_do_handshake` with a select() loop.
- After handshake, capture the negotiated ALPN protocol via
  `SSL_get0_selected` (OpenSSL 1.1+ API).
- The test does NOT need to send any application data — handshake
  completion is sufficient.
- If the production bug is reintroduced (ALPN not set in
  `tls_build_ssl_ctx`), the negotiated protocol will be empty
  (zero-length wire-format string) and the assertion will fail.

## Production fix details

In `tls_build_ssl_ctx`, after `SSL_CTX_set_session_cache_mode`,
add:

```c
if (cfg->alpn_len > 0) {
    if (SSL_CTX_set_alpn_protos(cfg->ssl_ctx, cfg->alpn_data,
                                 cfg->alpn_len) != 0) {
        SSL_CTX_free(cfg->ssl_ctx);
        cfg->ssl_ctx = NULL;
        return -1;
    }
}
```

This is a small, surgical change. It mirrors the existing code
in `cmq_tls_reload` (line 405-407 of the same file), so it's
verified-by-inspection against the reload path.
