# v0.5.101 — Response spans (D1 follow-up)

## Scope
`KIND_REQUEST` is on the ring. `handle_response` never
offers a span. This increment adds `KIND_RESPONSE` and
offers one after a successful local deliver.

## Design (performance-first, safety, reliability)

- One response span per successful local inbox deliver,
  not per subscriber.
- Same 16-byte accept `trace_id`.
- Failed deliver / no subscribers: no span.
- Route-only forward does not count (align request).
- `otel == NULL`: no-op.
- Offer stays non-blocking; drop-newest unchanged.
