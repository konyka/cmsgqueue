# v0.5.43 — MQTT 5.0 property decode

## Scope
R2 from v0.5.41/v0.5.42: PUBLISH/SUBSCRIBE treat the 5.0 Properties
region as a skip-only blob, and the skip is in the **wrong place**
(immediately after the topic, before Packet Identifier). Payload
offset is then recomputed as `topic + packet_id`, so property bytes
are delivered as payload. `mqtt_v5_props_skip` is also on for
3.1.1 sessions, so a 3.1.1 payload's first byte can be eaten as a
VBI. v0.5.43 decodes the property list and fixes the layout.

Also closes **R4**: `cmq_mqtt_server.h` still documents STUB/ENOSYS.

Remaining P2: R3 trace-id in logs, R5 WAL rotation, R6 MQTT
will/sessions, R7 connz/subz/routez.

## Design (performance-first, safety, reliability)

### Pure decoder

`cmq_mqtt_props_decode(buf, len, props)`:

1. Read Property Length (MQTT VBI, same as remaining length).
2. Walk `props_len` bytes. Known identifiers only; unknown → `-1`
   (fail-closed, no desync).
3. Strings/binary are **borrowed** pointers into `buf`. No malloc.
4. User properties capped at 4 (drop extras, still consume bytes).

Decoded fields used on PUBLISH: payload format, expiry, content
type, response topic, correlation data, topic alias, subscription
id. Other known MQTT 5 identifiers are skipped by type so a
CONNECT-style list still validates.

### PUBLISH layout (MQTT-5.0 §3.3.2)

```
topic_len + topic | [packet_id if QoS>0] | [properties if v5] | payload
```

`cmq_mqtt_publish_payload_off(vh, vh_len, qos, v5, props)` returns
the payload offset or `-1`. 3.1.1 (`v5=0`) does not look at a
property VBI.

### Session flag

`parse_connect` exposes `is_v5`. The client loop stores
`session_v5`. CONNECT, PUBLISH, and SUBSCRIBE decode properties
**only** when the session is MQTT 5.0.

### Safety

- Every read is bounds-checked against `props_len`.
- Unknown identifier → reject the packet (continue), no fan-out of
  a desynced payload.
- 3.1.1 unchanged: no property scan.

### Reliability

- Decoder is allocation-free and re-entrant.
- SUBSCRIBE property skip also gated on `session_v5`.
