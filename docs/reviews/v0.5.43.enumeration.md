# v0.5.43 — MQTT 5.0 retained-message + wildcard subscription delivery

## Scope
v0.5.26 ships dispatch-loop tests that verify `cmq_mqtt_topic_match`
returns the right set against a hand-built retained-topic store.
v0.5.43 adds an end-to-end test: PUBLISH-with-retain on a specific
topic, then a SUBSCRIBE on a wildcard pattern that matches, and
verify the broker delivers the retained message. This is the most
common MQTT retained + wildcard use case.

This is NOT a wire-format test — it uses the public
`cmq_mqtt_store_retained` + `cmq_mqtt_record_subscriber` + a
manual call to the dispatch fanout (mimicking what mqtt_handle_client
does on a real subscription request). A full MQTT wire round-trip
is v0.6 scope.

## Design

### Test flow (`tests/test_mqtt_retained_wildcard.c`)

1. Start the MQTT bridge path so `cmq_mqtt_set_bridge_server` is
   wired (uses srv == NULL to skip the actual relay thread; we just
   need the static `g_qos2_count` reset).
2. `cmq_mqtt_store_retained("sensors/temp", payload, 32)` — store a
   retained message.
3. `cmq_mqtt_record_subscriber("sensors/+")` — record a wildcard
   subscriber.
4. Call `cmq_mqtt_dispatch_retained("sensors/temp", payload, 32)`,
   which mimics what mqtt_handle_client does: applies
   `cmq_mqtt_topic_match` to each subscriber, and dispatches when
   matched. (This is a NEW test-only helper in v0.5.43.)
5. Assert the dispatch invoked the registered callback with the
   correct (subscriber_fd, payload).
6. Repeat for `sensors/#` and a literal `sensors/temp`.

### `cmq_mqtt_dispatch_retained` test-only helper

```c
/* v0.5.43: test-only. Walks the subscriber list (set by
 * cmq_mqtt_record_subscriber), applies cmq_mqtt_topic_match for
 * each subscriber, and "delivers" by calling a registered
 * callback. Production code's mqtt_handle_client does this
 * internally on a real SUBSCRIBE; this helper exposes the path
 * for unit testing. */
typedef void (*cmq_mqtt_test_dispatch_cb)(int subscriber_idx,
                                          const char *topic,
                                          const uint8_t *payload,
                                          size_t payload_len,
                                          void *user);

void cmq_mqtt_dispatch_retained(const char *topic,
                                  const uint8_t *payload,
                                  size_t payload_len,
                                  cmq_mqtt_test_dispatch_cb cb,
                                  void *user);
```

Implementation: walks `g_mqtt_sub_topics[]` (max 128 entries),
calls `cmq_mqtt_topic_match` for each, invokes cb on match.

### Safety

- All fields are test-only and documented as such.
- `cb` is invoked synchronously on the calling thread; no global
  state mutation during dispatch.

### Reliability

- The test uses small `g_mqtt_subs` reset hooks (or runs after
  a `cmq_mqtt_set_retained_path("")` which clears the buffer).
  Documented in the test.
