# CMSGQueue v0.5.12 — Remaining Gap Enumeration

**Scope.** Items deferred from v0.5.11 (which shipped 2 verification
tests) plus new gaps at HEAD (v0.5.11, commit 3311bc8, 75/75 tests).

## P1 — Multi-threaded accept loop

- **gap** → `src/server/cmq_server.c:712, 7069` (single listen fd
  registered with the ev_loop; accept_cb runs on the ev_loop
  thread). High connect rates bottleneck.
- **impact**: 100K+ conn/sec can't be served.
- **effort**: L (multi-threaded accept + per-conn handoff).

## P1 — Multi-listener runtime accept loop (carefully)

- **gap** → `src/server/cmq_server.c:7027` (cmq_server_run binds
  only `listen_fds[0]`; v0.5.10 rolled back because test_server
  expected port 7654 specifically). Need to bind extra ports
  carefully without breaking test_server.
- **impact**: cannot serve two distinct certs/ports from one process.
- **effort**: M (200 LOC: iterate slots, per-listener accept_cb;
  guard test_server's port with explicit-keep-on-7654 path).

## P1 — WS permessage-deflate

- **gap** → `src/server/cmq_ws.c` (extend WS handshake to negotiate
  `permessage-deflate; server_no_context_takeover`; per-conn z_stream).
- **impact**: bandwidth waste on WS clients.
- **effort**: L.

## P1 — 5.0 wildcard PUBACK match

- **gap** → `src/enterprise/cmq_mqtt_server.c` (no `+` wildcard

- **impact**: 5.0 compliance gap.
- **effort**: M.

## P1 — TLS session cache (real)

- **impact**: low.
- **effort**: S.

## P3 — Freelist overflow cap

- **effort**: S.

- **effort**: XS.

## Verdict

v0.5.12 must focus on:
- **Performance**: #1 multi-threaded accept (bench could double)
- **Functional**: #2 multi-listener (carefully), #3 WS deflate, #4 5.0 wildcard
- **Reliability**: #6 TLS regression test (real)

Multi-listener (#2) is the highest-value win since the data
structure has been in place since v0.5.2 — but v0.5.12 must
carefully avoid the test_server regression that rolled back
v0.5.10.
