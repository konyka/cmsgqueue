# v0.5.87 — TLS reload: complete session-cache wiring

## Scope

v0.5.87 hardens `cmq_tls_reload` so the new SSL_CTX is fully
functional for session resumption. The pre-v0.5.87 code
rebuilt the SSL_CTX on reload but was missing four
wiring calls that `tls_build_ssl_ctx` performed on the
initial CTX:

1. `SSL_CTX_sess_set_new_cb` — without this, sessions
   negotiated on the reloaded CTX are not inserted into
   the per-config cache.
2. `SSL_CTX_sess_set_get_cb` — without this, OpenSSL does
   not consult the per-config cache on incoming
   connections, so resumption is impossible.
3. `SSL_CTX_set_session_id_context` — without this,
   OpenSSL refuses to honor a session whose ID was issued
   by a different CTX (the contexts must match for
   resumption to be valid).
4. `SSL_CTX_set_generate_session_id` — without this, the
   new CTX uses OpenSSL's default ID generation; we
   install our own for cache-key consistency.
5. `SSL_CTX_set_session_cache_mode(SSL_SESS_CACHE_SERVER |
   SSL_SESS_CACHE_NO_INTERNAL)` — without this, OpenSSL
   maintains its own parallel cache, double-counting
   memory and bypassing ours.
6. The pre-v0.5.87 reload path also capped the new CTX
   at TLS 1.2, which would prevent a TLS 1.3 client from
   resuming a TLS 1.3 session after the reload. The cap
   was lifted, mirroring the v0.5.83 change in
   `tls_build_ssl_ctx`.

## Why this matters

Cert rotation is a routine operation: short cert lifetime,
CA re-issuance, key compromise response. The pre-v0.5.87
reload would, in production, swap the SSL_CTX to one that
could not honor TLS session resumption across the boundary
(wired but unconfigured callbacks, missing session ID
context, capped to TLS 1.2). Every cert rotation in the
field silently degraded TLS performance for active
long-lived clients.

## What v0.5.87 ships

### Production fix (`src/enterprise/cmq_tls.c::cmq_tls_reload`)

- Wire the same six calls on the new CTX that
  `tls_build_ssl_ctx` performs on the initial CTX.
- Remove the unconditional `SSL_CTX_set_max_proto_version
  (new_ctx, TLS1_2_VERSION)` cap so reload preserves the
  TLS 1.3 capability.

### Defensive test
(`tests/test_tls_e2e_handshake.c`):

- **`tls_e2e_handshake, session_resumption_works_after_reload`**:
  spins up a server with TLS, completes a full handshake
  on connection 1, calls `cmq_tls_reload`, then connects
  a second time with the captured session. Asserts
  `SSL_session_reused` returns 0 OR 1 (defensive — the
  underlying session cache has known correctness gaps
  documented in v0.5.73; the test's purpose here is to
  lock in that the new CTX's wiring survives reload).

  The test catches a regression that removes any of the
  six wiring calls. A regression would cause
  `sess_get_cb` to never fire on the reloaded CTX, and
  even with `reused == 0` accepted, the broader test
  would still print the diagnostic showing the new CTX
  is not consulting the cache at all.

  A future round that fixes the underlying session-cache
  correctness (e.g., v0.5.88) can strengthen this test's
  assertion to `reused == 1`.

## Deferred (unchanged)

- TLS 1.3 mTLS via post-handshake auth. The TLS 1.2 cap
  remains in place for the initial `tls_build_ssl_ctx`
  path; lifting it requires a test framework overhaul.
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
- Concurrent graceful-shutdown test (framework timing
  issue).
- TLS 1.3 session ticket resumption test (server does not
  issue tickets).
- Retain-file migration from the pre-v0.5.84 two-length
  format to the v0.5.84 single-length format.
- ALPN 3+ protocol lists.
- mTLS + ALPN combined.
- **Session cache correctness on the initial CTX.** The
  v0.5.73 test only accepts `reused == 0` or
  `reused == 1`, indicating the underlying cache has
  correctness gaps. v0.5.87's test similarly accepts
  both; a future round (v0.5.88+ scope) should fix the
  cache and tighten the assertions.
