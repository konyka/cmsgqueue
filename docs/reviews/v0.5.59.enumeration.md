# v0.5.59 — idle TLS client defensive test

## Scope

A TCP client connects to a TLS-enabled server but never sends
any data (no ClientHello, no anything). The server's
`cmq_tls_handshake` returns 0 (WANT_READ) on every wakeup
because there's nothing to read. The server must eventually
clean up the half-open client when the TCP fd closes.

Before v0.5.45, this code path was unaffected by the bug
(SSL_do_handshake returns WANT_READ, not 1, when there's no
data). But a regression in the cleanup logic could leak
half-open client fds. This test guards against that.

## Test: `tls_e2e_handshake.idle_tls_client`

1. Spin up a TLS-enabled `cmq_server`.
2. Open a TCP connection (no data sent).
3. Wait a beat (server sits in WANT_READ loop).
4. Close the socket abruptly.
5. Wait for server cleanup.
6. `cmq_server_stop` + `pthread_join` must complete in bounded
   time (server isn't stuck on the dead fd).
