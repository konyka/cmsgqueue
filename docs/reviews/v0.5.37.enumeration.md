# v0.5.37 — Persistent subscriber restart-recovery test

## Scope
v0.5.7 / v0.5.19 ship unit tests for the F5 WAL file format and the
F11 sublist-persist file format in isolation. The end-to-end
recovery path — `cmq_server_create` opening both files, replaying
the WAL, and re-inserting persisted subscriptions — was only
covered by manual testing. v0.5.37 closes that gap with an
end-to-end test that creates a server, records a subscription,
destroys the server, recreates it with the same `persist_dir`, and
verifies the subscription is recovered.

## Design

### Test flow (`tests/test_persist_restart.c`)

1. `system("rm -rf /tmp/cmq-test-v0537-restart")` + mkdir.
2. `cmq_config_t cfg = { ..., persist_dir = ... }`.
3. Phase 1: `cmq_server_create(&srv_a, &cfg)` → `cmq_sublist_persist_record_sub(...)`
   for "v0.5.37/sentinel". Close the persist file. `cmq_server_destroy(srv_a)`.
4. Phase 2: `cmq_server_create(&srv_b, &cfg)` (same persist_dir).
5. Assert `cmq_sublist_count(srv_b->sublist) >= 1`.
6. Assert `cmq_sublist_match(srv_b->sublist, "v0.5.37/sentinel", &result)`
   returns 1 subscriber.

### Safety

- Tests use a unique `/tmp/cmq-test-v0537-restart` directory; no
  global state pollution.
- `system("rm -rf ...") + mkdir` pattern matches the existing
  `test_recover.c` and `test_sublist_persist.c` conventions.
- No real ports are bound (port=25070 may collide with other tests,
  but the test doesn't actually `cmq_server_run`; the event loop
  is never started).

### Reliability

- The end-to-end recovery is deterministic given a clean
  filesystem. The test uses `cmq_sublist_count` + `cmq_sublist_match`
  for verification — both atomic reads.

## TDD phases
1. **Red**: write the test. It will fail at runtime (not at build)
   if recovery is broken. The test as written passes immediately
   because v0.5.7 + v0.5.19 already shipped working recovery.
   This is a smoke test that LOCKS IN the existing behavior — any
   regression in the recovery path will fail this test.
2. **Green**: no production changes needed; the test passes on
   first build.
3. **Verify**: full ctest.

## Risk
- The test asserts `cmq_sublist_count >= 1` rather than `== 1`
  to tolerate future enhancements (e.g., per-account default subs).
- `cmq_sublist_match` may return more than 1 if a wildcard
  subscription is also recovered, but the test uses a literal
  subject "v0.5.37/sentinel" so only exact matches count.

## Honest caveat
The test calls `cmq_server_create` twice in the same process. This
is equivalent to a real restart (the second call has no state from
the first; the persist file is the only thing carried over). A
true fork-exec test would be more thorough but is much harder to
write in the existing test framework.
