# v0.5.51 — Emit the dead audit events

## Scope
`cmq_audit_log` already knows `auth_ok`, `auth_fail`,
`persist_fail`, `persist_recover`, `tls_handshake_fail`.
Production only emitted `rate_limit_reject` (blocklist +
connect quota). Docs claimed F8 logged auth; it did not.

D1–D6 stay deferred. ALPN does not currently call
`cmq_tls_set_alpn` (the `h2` risk is comment-only).

## Design (performance-first, safety, reliability)

- **Not on successful PUBLISH.** Persist-fail is the WAL error
  path (append already failed). Recover is once at startup.
  Auth and TLS are CONNECT / accept.
- `cmq_audit_auth` is the only new helper: `ok` + trace + user
  + reason. **Never a password.**
- Hashed-verify hard fail and the padded compare share
  `auth_fail` so the audit line does not leak which check lost.
- `auth_ok` only when `auth_configured` and credentials passed.
