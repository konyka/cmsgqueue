# v0.5.51 — garbage TLS record defensive test

## Scope

v0.5.50 added a defensive test for mid-handshake disconnect.
v0.5.51 adds a parallel test for an invalid TLS record
header — a TLS client that sends bytes that look like a valid
record but contain a bogus record type (0xff). OpenSSL
rejects the record with `SSL_ERROR_SSL`; the server's
`cmq_tls_handshake` returns -1; `client_tls_handshake`
destroys the session and rejects the connection.

The test asserts the server doesn't hang on the bad fd (same
regression guard as v0.5.50, but for a different error path).

## Test: `tls_e2e_handshake.garbage_tls_record`

```c
/* Send a valid-looking TLS record header but with an invalid
 * record type (0xff). OpenSSL rejects unknown record types. */
int cfd = open_tcp(25523);
uint8_t bad[5] = {0xff, 0x03, 0x03, 0x00, 0x01};
write(cfd, bad, sizeof(bad));
nanosleep({0, 500000000});  /* give server time to reject */
close(cfd);
nanosleep({1, 0});           /* wait for cleanup */
cmq_server_stop(srv);
pthread_join(tid, NULL);
cmq_server_destroy(srv);
```

## What v0.5.51 ships

Just the test. No production change — the v0.5.45 fix already
handles bad-record rejection correctly.
