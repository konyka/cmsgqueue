# v0.5.47 — connz / subz / routez

## Scope
R7 from v0.5.41: `/healthz` `/readyz` `/metrics` exist; there is
no per-connection, per-subscription, or per-route introspection
(NATS `connz` / `subz` / `routez`). This is the last P2 item.

P3 (OTel, HTTP/2, JWT, JetStream, EOS, Kafka compact, subject
rewrite, per-account hard limits) stays deferred.

## Design (performance-first, safety, reliability)

### Pure formatters

`cmq_monitor_format_{connz,subz,routez}` write JSON from a
caller-provided snapshot. No locks, no heap. Unit-tested on any
host.

### Snapshot then format

The HTTP handler copies at most 64 conns / 256 subs / 32 routes
under the existing client/route locks, then formats after unlock.
Publish path is untouched.

### Safety

- User/account/subject strings are JSON-escaped (CWE-116).
- No passwords, no wire secrets.
- Response capped at 8 KiB; overflow sets `"truncated":1`.
