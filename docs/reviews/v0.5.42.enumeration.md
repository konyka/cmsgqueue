# v0.5.42 — Second accept thread actually admits

## Scope
v0.5.41 catalogued R1: `accept_thread_func` (`cmq_server.c`) accepts
a client and immediately `close(client_fd)`. The wait condition is
also inverted (`while (!running && !drain)`), so the thread only
runs in the startup window, then exits. Extra-listener connections
that lose the race with the main `accept_cb` during that window
are dropped. v0.5.42 closes R1.

Remaining P2 after this round: R2 MQTT 5.0 property decode, R3
trace-id in logs, R4 MQTT header STUB drift, R5 WAL rotation,
R6 MQTT will/sessions, R7 connz/subz/routez.

## Design (performance-first, safety, reliability)

### Extract `admit_one_client`

The post-`accept()` path in `accept_cb` (max_clients CAS, per-IP
rate limit, TLS slot, worker handoff) becomes
`admit_one_client(srv, listen_fd, client_fd, addr)`. Both the
main event-loop callback and the aux thread call it. One
admission policy, no duplicated rate-limit/TLS logic.

### Aux thread lifecycle

1. Spawn **after** workers exist, **before** `running=1`.
2. Wait until `running` (workers published) or `drain`.
3. Loop `while (running && !drain)` with `epoll_wait(..., 100)`.
4. On accept: `admit_one_client`. On success, increment
   `stat_accept_aux`.
5. Joinable (`cmq_thread_create` + join after `ev_run`), not
   detached — avoids UAF if destroy races the thread.

### Which fds

Watch **all** `listen_fds[i] >= 0`, including slot 0. Two threads
`accept()` on the same listening socket is the standard Linux
pattern (thread-safe). Extra listeners stay on the main `ev_loop`
(v0.5.18 tests unchanged). Parallel accept raises admit
throughput under connection bursts.

### Safety

- Same `max_clients` CAS and rate-limit as `accept_cb`.
- TLS slot from the listen fd (`srv_find_tls_slot`).
- Drain/stop: leftover `client_fd` is closed; no new admits.
- Init every `listen_fds[i]` to `-1` (calloc left them 0 / stdin).

### Reliability

- Do not admit until `running=1` (workers + idmap exist).
- Join before listen fds are closed.
- 64 accepts per wake (same cap as `accept_cb`).
