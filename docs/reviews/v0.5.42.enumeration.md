# v0.5.42 — MQTT QoS2 retransmit helpers + test

## Scope
The MQTT server has a per-session QoS2 retransmit table
(`g_qos2[MQTT_QOS2_MAX]`) since v0.5.3. The two helpers
`qos2_record_or_lookup` and `qos2_get_phase` are `static`. No
test exercises them directly. v0.5.42 exposes them as
**test-only** helpers and ships a unit test that verifies the
record/lookup/update semantics that drive MQTT v3.1.1 QoS2
re-delivery (PUBLISH → PUBREC → PUBREL → PUBCOMP).

This is NOT an end-to-end MQTT wire-format test (those need a real
MQTT client over TCP; v0.6 scope). It's a smoke test that
verifies the table-management code that the wire handler relies
on. Catches regressions in add / lookup / update / overflow.

## Design (performance-first, safety, reliability)

### Public test-only API

In `cmq_mqtt_server.h`:
```c
/* v0.5.42: test-only. Insert or update a packet_id's QoS2 phase.
 * Returns 1 on update (entry existed), 0 on insert (new entry),
 * -1 if the table is full. */
int cmq_mqtt_qos2_record_or_lookup_test(uint16_t packet_id, int new_phase);

/* v0.5.42: test-only. Return the phase (1 PUBREC, 2 PUBCOMP) or
 * 0 if not found. */
int cmq_mqtt_qos2_get_phase_test(uint16_t packet_id);
```

Implementation: thin wrappers in cmq_mqtt_server.c that forward to
the static helpers. Used only by `tests/test_mqtt_qos2.c`.

### Test flow (`tests/test_mqtt_qos2.c`)

1. Empty table: `qos2_get_phase_test(42) == 0`.
2. Insert new: `qos2_record_or_lookup_test(42, 1) == 0`.
   Get: `1`.
3. Update: `qos2_record_or_lookup_test(42, 2) == 1` (existing).
   Get: `2`.
4. Different packet_id: `qos2_record_or_lookup_test(43, 1) == 0`.
   Both `42 → 2`, `43 → 1`.
5. Overflow: insert MQTT_QOS2_MAX=128 entries with distinct IDs;
   the (128+1)th returns -1.

### Safety

- The test-only helpers are documented as test-only; production
  code doesn't call them.
- The wrappers preserve the original `qos2_record_or_lookup` /
  `qos2_get_phase` semantics exactly.

### Reliability

- The retransmit table is global state (intentional — MQTT server
  is single-process for the demo). The test exercises the table
  but doesn't reset between tests; each test uses distinct packet
  IDs to avoid collisions.
- The overflow test fills to MQTT_QOS2_MAX then verifies the
  (MAX+1)th returns -1. Other tests after this one may see a
  full table; documented as a limitation.

## Risk
- The wrappers expose static state; a careless test could leave
  the table populated and affect later tests. The test uses
  unique packet IDs (random or offset-by-test) to avoid this.
