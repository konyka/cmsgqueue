# v0.5.34 — MQTT bridge freelist load test

## Scope
v0.5.8 added the `g_mqtt_bridge_freelist` (capped at 64 entries) for
recycling MQTT payload buffers. v0.5.19 added a smoke test that
exercises `cmq_mqtt_store_retained` 1000 times — but that
function doesn't touch the freelist. v0.5.34 ships a real load
test that exercises the relay path where the freelist actually
gets used.

## Design (performance-first, safety, reliability)

### Test-only helpers

Add two helpers in `cmq_mqtt_server.c` (test-only, no production
use):

```c
/* Test-only: push a payload onto the bridge queue. Returns 0 on
 * success, -1 if the queue is full. The relay thread will pop it
 * and push the payload to the freelist (subject to the cap). */
int cmq_mqtt_test_enqueue_bridge(const char *topic, const uint8_t *payload,
                                    size_t len);

/* Test-only: read the current freelist occupancy. */
int cmq_mqtt_test_freelist_count(void);
```

The enqueue helper duplicates `mqtt_handle_client`'s
queue-fill code (lines 823-827). Both helpers guarded by `#ifdef
CMQ_TEST_BUILD` or by a CMake test-only flag (simplest: declare
them unconditionally in the header but only link them when
the test object is built; the .c file builds them always).

### Test flow

1. Start the relay thread by calling `cmq_mqtt_set_bridge_server`
   (which spawns the relay thread per v0.5.3).
2. Enqueue 200 small payloads via `cmq_mqtt_test_enqueue_bridge`.
3. Sleep 100 ms to let the relay thread drain them all.
4. Read `cmq_mqtt_test_freelist_count()`. It must be ≤ 64.

### Safety

- Test-only helpers are documented as such in the header. Production
  code never calls them.
- The relay thread is already gracefully shut down by
  `cmq_mqtt_bridge_shutdown`. The test calls that in teardown.
- 100ms sleep is bounded — if the relay is wedged, the test
  fails on the `freelist_count > 64` assertion (the cap is
  enforced, but the count stays at 64 max).

### Reliability

- 200 messages is enough to overshoot the 64-cap if it were
  broken. The freelist caps at 64 by design (line 186–193).
- Test is deterministic; no time-of-day dependencies.

## Risk
- The test-only enqueue helper bypasses the normal MQTT wire
   protocol. If the helper is buggy (e.g., forgets to set
   `g_mqtt_bridge_payloads[i] = NULL`), the relay thread could
   double-free. Mitigation: copy the producer logic exactly and
   add an assertion in the test that payloads are NOT
   double-freed (e.g., by setting a sentinel after relay).
