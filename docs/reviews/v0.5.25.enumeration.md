# v0.5.25 — MQTT topic matcher extraction + real PUBACK-style wildcard test

## Scope
The MQTT 5.0 `+` single-level wildcard matcher is currently buried in
`src/enterprise/cmq_mqtt_server.c:690-707` (inside the SUBSCRIBE → retained
dispatch loop). It is not directly callable, so the existing test
(`tests/test_mqtt_5_wildcard.c`) is a placeholder that just asserts 1.

v0.5.25 extracts the matcher to a public function
`cmq_mqtt_topic_match(const char *pattern, const char *topic)` and writes
a real test that exercises it directly. The dispatch loop continues to
use the new function (refactor-in-place, no behavior change).

This unlocks:
- Direct unit testing of the matcher.
- Future use from cmq_sublist or anywhere else that needs MQTT topic
  matching.
- A regression sentinel for the `+` semantics.

## Design (performance-first, safety, reliability)

### Extracted API

```c
/* MQTT 5.0 topic matcher.
 *   pattern: SUBSCRIBE filter string, may contain `+` and `#` wildcards.
 *   topic: PUBLISH topic string (no wildcards).
 *   Returns 1 on match, 0 on no match, -1 on invalid input.
 *
 * `+` matches exactly one MQTT topic level (no `.` in that segment).
 * `#` matches zero or more remaining levels (must be the last character
 *   or alone).
 * Topics without wildcards match only exact strings.
 */
int cmq_mqtt_topic_match(const char *pattern, const char *topic);
```

### Performance
- Linear scan, no allocations. O(min(|pattern|, |topic|)).
- Single tokenization pass — count dots in pattern and topic; reject
  if `+` count + literal token count disagree with topic token count.

### Safety
- NULL inputs return -1.
- Length cap (`MQTT_MAX_TOPIC_LEN = 256`) is applied to both inputs.
- `#` not at end of pattern → return -1 (invalid wildcard position per
  MQTT 5.0 spec).
- Multiple `#` → return -1.

### Reliability
- Pure function, no globals, no locks. Easy to fuzz.

## Test cases

| Name | Verifies |
|---|---|
| `exact_match` | `"foo/bar"` matches `"foo/bar"`, not `"foo/baz"` |
| `single_wildcard` | `"foo/+"` matches `"foo/bar"`, `"foo/baz"`; not `"foo/bar/baz"` |
| `multi_level_wildcard` | `"foo/#"` matches `"foo/bar"`, `"foo/bar/baz"`, `"foo/"` |
| `wildcard_first_level` | `"+/bar"` matches `"foo/bar"`, not `"foo/baz"` |
| `wildcard_only` | `"#"` matches any topic |
| `no_match_different_lengths` | `"foo/bar"` does not match `"foo"` |
| `invalid_pattern_returns_neg` | `"foo/#/bar"` → -1 (multi-level not at end) |
| `null_inputs_rejected` | NULL pattern or topic → -1 |
