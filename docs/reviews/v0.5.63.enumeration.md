# v0.5.63 — NKEY on CONNECT (D3 phase 2)

## Scope
`cmq_nkey_verify` exists. CONNECT still cannot present an
Ed25519 signature. This increment wires `nkey_pub` (64 hex
chars) so the password field is a hex signature of
`CMQNK1|<username>`.

JWKS and nkey seed/base32 codecs stay deferred.

## Design (performance-first, safety, reliability)

- No `nkey_pub`: one pointer check.
- Verify on the CONNECT worker (not accept).
- Fixed message prefix so a signature cannot be replayed
  against a raw JWT or password.
- Username required. Signature is 128 hex chars (64 bytes).
- JWT mode, when set, still wins (one auth method).
