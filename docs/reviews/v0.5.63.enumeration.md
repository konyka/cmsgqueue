# v0.5.63 — client trusts server cert directly defensive test

## Scope

A common operational pattern is self-signing the server cert
and putting it directly in the client's trust store (without
extracting a separate CA). This is a single-cert "chain" —
the leaf is in the trust store directly. The v0.5.46 chain
validation should accept this.

## Test: `tls_e2e_handshake.client_trusts_server_cert_directly`

1. Generate a self-signed server cert (no separate CA).
2. Configure `cmq_server` with `tls_cert` + `tls_key`.
3. Connect with a client that trusts the server cert
   **directly** (not a CA bundle).
4. Assert the handshake succeeds.
