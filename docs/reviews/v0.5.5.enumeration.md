# CMSGQueue v0.5.5 — Remaining Gap Enumeration

**Scope.** Items deferred from v0.5.4 (which shipped 12/13 P-items) plus new
gaps at HEAD (v0.5.4, commit 44702dd, 70/70 tests, ~31K msg/s).

## Sources

- `docs/reviews/v0.5.4.enumeration.md` — adversarial 13-item catalog.
- `docs/reviews/v0.5.4.plan.md` — 4-phase WBS.
- v0.5.4 follow-ons from the ultrabrain review.

## P1 — async WAL max payload size cap

- **gap** → `src/store/cmq_filestore.c:760` (cmq_filestore_async_enqueue
  accepts any payload size; a buggy MQTT client could OOM by
  sending huge payloads). The synchronous path has a 16 MiB cap
  (line 460) but the async path doesn't.
- **impact**: trivial OOM under hostile load.
- **effort**: S (5 LOC + a sub-test).

## P1 — sublist_insert no-leak on copy-malloc failure

- **gap** → `src/store/cmq_filestore.c:818` (cmq_filestore_async_enqueue
  returns -1 if `copy = malloc(len)` fails, but the slot is still
  consumed via `head++` ahead of the check). The producer sees
  -1 but the ring pointer has advanced — a silent slot leak.
- **impact**: bounded ring with hidden permanent failures.
- **effort**: S (move the malloc before the head++).

## P1 — rate-limit per (source IP, account) on MQTT PUBLISH

- **gap** → `src/enterprise/cmq_mqtt_server.c:581` (no rate limit
  on MQTT PUBLISH — a single client can flood the bridge).
- **impact**: trivial DoS by one client.
- **effort**: M (hash by (source IP, account_name) → token bucket).

## P1 — bridge cleanup on disconnect

- **gap** → `src/enterprise/cmq_mqtt_server.c:96` (g_mqtt_sub_topics
  + g_qos2 cleared on CONNECT per v0.5.4 P4, but the bridge
  queue g_mqtt_bridge_topics/payloads is separate). When the
  mqtt_thread exits, in-flight bridge entries are leaked.
- **impact**: small leak per session.
- **effort**: S (free entries on thread exit).

## P2 — per-message-deflate for WebSocket transport

- **gap** → `src/server/cmq_ws.c` (WS permessage-deflate is not
  negotiated; clients must compress manually).
- **impact**: bandwidth waste on WS clients.
- **effort**: L (deflate state per connection).

## P2 — WRITER_FAIRNESS on sublist rwlock

- **gap** → `src/server/cmq_sublist.c:24, 433` (writers can
  starve readers under continuous subscribe/unsubscribe; no
  PTHREAD_RWLOCK_PREFER_READER_NP or equivalent).
- **impact**: publish latency spikes under constant churn.
- **effort**: M (depends on the underlying cmq_rwlock implementation).

## P3 — TLS load() partial-state cleanup on failure

- **gap** → `src/enterprise/cmq_tls.c:331` (if cmq_tls_load fails
  mid-way, partial state leaks: alloc cipher list, etc.). On
  failure, free what was allocated.
- **impact**: small leak on bad config.
- **effort**: XS (cleanup on each early-out path).

## P3 — close-by-fd protection in cmq_clients[]

- **gap** → `src/server/cmq_server.c` (cmq_clients[] is indexed by
  fd; if a close and re-bind happen before the old close_cb runs,
  the new client gets clobbered). v0.5.1's accept_cb likely has
  protection but worth verifying.
- **impact**: rare race.
- **effort**: S (compare-and-swap guard).

## P3 — accept loop single-threaded

- **gap** → `src/server/cmq_server.c:712` (cmq_ev_add with one
  listen_fd — ev_loop is single-threaded by default). High conn
  rates bottleneck.
- **impact**: 100K+ conn/s can't be served.
- **effort**: L (multi-threaded accept + per-conn handoff).

## P3 — stat_messages_out not split by live/replay

- **gap** → `src/server/cmq_server.c:2191` (stat_messages_out
  increments for replayed messages too, same as the v0.5.3 P2
  message_in issue). v0.5.4 P4 didn't address this.
- **impact**: ops misreads "messages out" during startup.
- **effort**: XS.

## P2 — Redis pubsub-compatible wire protocol

- **gap** → no source file (entirely missing). The cmq server
  speaks only its native protocol; clients cannot use a Redis
  SDK.
- **impact**: very large client ecosystem locked out.
- **effort**: XL (full new wire protocol).

## P3 — JWT auth

- **gap** → `src/server/cmq_server.c` (auth is username/password
  SHA-256 only via cmq_auth). No JWT / token-based auth.
- **impact**: limited interoperability with modern auth systems.
- **effort**: L (token decode + verify, claim extraction).
