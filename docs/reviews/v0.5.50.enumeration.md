# v0.5.50 — defensive test for the v0.5.45 TLS handshake resume

## Scope

v0.5.45 fixed a critical TLS handshake bug where the server's
`client_tls_handshake` returned `-1` on `SSL_do_handshake`
returning `1` (synchronous success), silently killing the
connection. v0.5.45 changed the code to keep the session alive
on `rc == 1` and only destroy on `rc < 0` (real error).

The v0.5.45 tests verify the happy path and the rejection path,
but **no test covered the mid-handshake disconnect path**:
a TLS client that connects, sends partial bytes, then closes
the socket before completing the handshake. If the server's
read-path resume didn't handle this correctly, the worker
would either spin indefinitely or leave the client in a
half-state, blocking the accept thread.

v0.5.50 adds a defensive test that exercises this exact path:
partial ClientHello + abrupt close. The test asserts:
1. The server doesn't crash.
2. The server's event loop detects the closed fd via the
   `cmq_tls_handshake → SSL_do_handshake → SSL_ERROR_SYSCALL
   → -1` path.
3. `cmq_server_stop` followed by `pthread_join` returns
   within a bounded time (server isn't stuck).

## Test: `tls_e2e_handshake.mid_handshake_disconnect`

```c
/* Connect, send partial ClientHello, close abruptly. */
int cfd = open_tcp(25522);
uint8_t partial[9] = {
    0x16, 0x03, 0x03, 0x00, 0x04,  /* TLS record header: handshake v1.2 */
    0xaa, 0xbb, 0xcc, 0xdd          /* 4 bytes of garbage */
};
write(cfd, partial, sizeof(partial));
nanosleep({0, 200000000});  /* give server time to read */
close(cfd);                 /* abrupt close */
nanosleep({1, 0});          /* wait for cleanup */

cmq_server_stop(srv);
pthread_join(tid, NULL);
cmq_server_destroy(srv);
```

## What v0.5.50 ships

Just the test. No production change — the v0.5.45 fix already
handles this case correctly. The test is a regression guard.

## Verified

- `tests/test_tls_e2e_handshake.c::mid_handshake_disconnect` PASS.
- Full ctest: 89/89 pass.
- Bench: ~32K msg/s, p99 99 µs (unchanged).
