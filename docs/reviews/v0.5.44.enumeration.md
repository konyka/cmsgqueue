# v0.5.44 — Trace ID in log lines

## Scope
R3 from v0.5.41: `cmq_trace_id` is documented as a per-connection
correlation ID, but log lines never include it
(`docs/features/tracing.md`). CONNECT assignment is also inverted:
`calloc` zeros `trace_id`, then the loop treats any zero byte as
"already assigned" and skips `cmq_trace_id`, so every connection
keeps an all-zero ID.

R2/R4 closed in v0.5.43. Remaining P2 after this round: R5 WAL
rotation, R6 MQTT will/sessions, R7 connz/subz/routez.

## Design (performance-first, safety, reliability)

### Assign once at accept

`cmq_client_create` calls `cmq_trace_assign` (one `RAND_bytes(16)`
+ hex encode into `c->trace_hex[33]`). CONNECT only backfills if
hex is empty. Cost is on the accept path, not PUBLISH.

### Thread-local, no call-site rewrite

`cmq_log_set_thread_trace(hex)` stores a borrowed pointer. Format
becomes `[LEVEL] [time] [tid=hex] file:line: msg` when set;
unchanged when unset (existing tests keep passing).

`client_dispatch_parser` sets TLS around `handle_frame` and
clears after. Hot PUBLISH that does not log pays two pointer
stores.

### Safety

- Only 32 lowercase hex chars are accepted (reject junk / injection).
- ID is not placed on the wire.
- Blocklist audit uses `c->trace_hex` instead of NULL.
