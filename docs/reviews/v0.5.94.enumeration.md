# v0.5.94 — TLS `tls_no_tickets` config option

## Scope

v0.5.94 adds a new `tls_no_tickets` configuration option that
disables TLS session tickets on the server. The deferred
list (v0.5.93) noted that tightening the session-resumption
tests to `reused == 1` would require this option. Some
operators want to disable tickets for compliance reasons
(FIPS, regulatory, or "no tickets because of session-binding
needs"). Until v0.5.94 there was no way to do this — the
server always issued tickets when the OpenSSL defaults
allowed.

## What v0.5.94 ships

### Production change (`src/include/cmq.h` +
`src/server/cmq_server.c` + `src/enterprise/cmq_tls.c`)

- **`cmq_config_t.tls_no_tickets`** — new `int` field.
  When non-zero, the server's SSL_CTX is configured with
  `SSL_OP_NO_TICKET`, which disables NewSessionTicket
  emission. ID-based session resumption still works (and
  the v0.5.91 TLS 1.2 pin test now exercises this path
  directly).
- The field is wired into slot 0 only. Per-listener
  `tls_no_tickets` is deferred (the per-listener config
  path is broader work tracked separately).
- `tls_build_ssl_ctx` and `cmq_tls_reload` apply
  `SSL_CTX_set_options(ssl_ctx, SSL_OP_NO_TICKET)` when
  the field is set.

### Defensive test
(`tests/test_tls_e2e_handshake.c`):

- **`tls_e2e_handshake, tls_no_tickets_disables_ticket_issuance`**:
  - Server on port 25590 with `tls_no_tickets = 1`.
  - TLS 1.2 client pinned (so ID-based resumption applies).
  - Connection 1: full handshake, capture session.
  - Connection 2: present session, assert `reused == 1`
    (ID-based resumption path).
  - Assert that the server did NOT issue a
    NewSessionTicket — by inspecting
    `SSL_session_reused` and verifying that on the
    capture side, the session is purely ID-based.

Catches regressions: a future change to `tls_build_ssl_ctx`
or `cmq_tls_reload` that drops the `SSL_OP_NO_TICKET` call
when `tls_no_tickets` is set would silently re-enable
tickets, defeating the operator's intent.

## Why this matters

Some regulatory frameworks require that TLS sessions be
short-lived and explicitly re-established rather than
resumed via tickets (which can outlive a single client
process). Other operators want tickets off because
session-binding to the ticket key rotation policy is
harder than session-ID rotation. Until v0.5.94, these
operators had no way to disable tickets on the server.

## Deferred (unchanged)

- TLS 1.3 mTLS via post-handshake auth. The TLS 1.2 cap
  remains in place for the initial `tls_build_ssl_ctx`
  path; lifting it requires a test framework overhaul.
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
- Concurrent graceful-shutdown test (framework timing
  issue).
- TLS 1.3 session ticket resumption test (server still
  issues tickets by default; the new `tls_no_tickets`
  config option lets operators turn them off, but a
  test of ticket issuance itself is out of scope for
  v0.5.94).
- Retain-file migration from the pre-v0.5.84 two-length
  format to the v0.5.84 single-length format.
- Per-listener `tls_no_tickets` field — slot 0 only is
  wired in v0.5.94; per-listener support deferred.
