# v0.5.72 — graceful TLS shutdown via close_notify

## Scope

Defensive test + production fix for a real bug: when
`cmq_server_stop` runs with active TLS connections, the server
abruptly closes the underlying fd without sending a TLS
`close_notify` alert. The client observes `SSL_ERROR_SYSCALL`
and `EBADF` on the raw fd, with `SSL_get_shutdown()` returning
0 (no `SSL_RECEIVED_SHUTDOWN`). This degrades the client
experience: well-behaved TLS libraries (e.g., pyftplib,
requests, Java HttpClient) may log errors or attempt retries.

The pre-fix `cmq_tls_session_destroy` called `SSL_shutdown`
followed immediately by `SSL_free` + fd close. OpenSSL's
`SSL_shutdown` writes the close_notify alert into the BIO
buffer but doesn't flush it to the kernel — `SSL_free` runs
before the buffer is drained. The result: close_notify is lost.

## Test: `tls_e2e_handshake.graceful_shutdown_close_notify`

After a full TLS handshake, stop and destroy the server, then
read on the client side. Assert:
1. `SSL_get_shutdown() & SSL_RECEIVED_SHUTDOWN` is set.
2. `SSL_read` returns 0 with `SSL_ERROR_ZERO_RETURN` (graceful).

## Fix

1. New `cmq_tls_session_graceful_shutdown()` in
   `src/enterprise/cmq_tls.c`. Loops `SSL_shutdown` with short
   `select(0, NULL, NULL, NULL, &tv)` waits so the BIO can
   flush the close_notify alert. Bounded to 4 iterations to
   bound latency. Returns 1 on full bidirectional close, 0 on
   partial (our close_notify sent, peer didn't ack), -1 on
   error.

2. In `client_teardown()` in `src/server/cmq_server.c`,
   call `cmq_tls_session_graceful_shutdown()` BEFORE
   `cmq_ev_del(c->ev_loop, c->fd)`. If we delete the fd from
   the polling loop first, the BIO can never flush. The
   shutdown must run while the ev_loop still owns the fd.

3. `SSL_shutdown` in the existing `cmq_tls_session_destroy`
   is kept as a fallback for any path that doesn't go through
   `client_teardown`. `SSL_free` follows; if the close_notify
   alert is still in the BIO buffer it will be lost (this is
   the pre-fix behavior — acceptable as a final best-effort).

## Verified

- `tests/test_tls_e2e_handshake.c::graceful_shutdown_close_notify` PASS (5/5 runs).
- Full ctest: 110/110 pass.
- Bench: ~34K msg/s, p99 99 µs (unchanged from v0.5.71).
