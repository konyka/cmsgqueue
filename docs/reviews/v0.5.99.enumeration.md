# v0.5.99 — Invalid middle listener slot preserves later listeners

## Scope

v0.5.98 covered an invalid certificate/key pair on the final
listener slot (slot 3) and verified fallback to global slot 0.
v0.5.99 covers the more important middle-slot case: an invalid
slot 1 must not poison a later valid slot 2.

## What v0.5.99 ships

- **`tests/test_tls_e2e_handshake.c::tls_invalid_middle_slot_preserves_later_listener`**:
  - Global slot 0 has valid credentials.
  - Slot 1 has a mismatched certificate/key pair.
  - Slot 2 has valid, distinct credentials.
  - Assert server creation succeeds and slot 1 is discarded.
  - Assert slot 2 remains initialized and complete a real
    handshake on its listener port using slot 2's valid CA/cert.

The test proves that the per-listener load-failure branch is
isolated: a failed middle slot does not stop the setup loop,
shift later slots, or leave the later valid listener unusable.

## Coverage by concern

- 45 TLS e2e tests after v0.5.99.
- Per-listener invalid-credential fallback now covers both
  the final slot boundary and a middle slot with a later valid
  listener.

## Deferred

- TLS 1.3 mTLS post-handshake auth.
- TLS 1.3 session ticket issuance and rotation.
- Retain-file migration from the pre-v0.5.84 format.
