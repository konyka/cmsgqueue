# v0.5.56 — cross-CA rejection defensive test

## Scope

The v0.5.46 mTLS pipeline calls `SSL_CTX_load_verify_locations`
with the configured `tls_ca` path. This test verifies that
the CA bundle trust chain actually filters out certs signed
by other CAs.

## Test: `tls_e2e_handshake.mtls_cross_ca_rejected`

1. Generate two independent CAs (ServerCA, ClientCA).
2. Sign a server cert with ServerCA and a client cert with
   ClientCA.
3. Configure `cmq_server` with `tls_ca=ServerCA` (trust
   ServerCA only — not ClientCA).
4. Connect with the client cert signed by ClientCA.
5. Assert the handshake fails.

If the CA bundle were silently widened (e.g., `tls_ca=NULL`
or pointing at the wrong file), the chain check might accept
the ClientCA-signed cert. This test guards against that
regression.
