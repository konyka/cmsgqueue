# v0.5.126 — reload MQTT bridge maps

## Scope
Create copies `mqtt_bridge_map` onto the live bridge.
`cmq_server_reload` loaded those rows into `fresh` and
freed them, so changing a mapping required a restart.

## Design (performance-first, safety, reliability)

- `cmq_mqtt_reload_maps` replaces the table under the
  bridge lock (same lock as outbound publish).
- n==0 / omitted keeps the current maps.
- Empty subject/topic or qos outside 0–2 fails closed
  before any store.
- No bridge (addr unset at create) skips the apply.
- Addr/port reconnect stays create-time.
