# v0.5.60 — cert/key mismatch defensive test

## Scope

A misconfigured `tls_cert` paired with a non-matching `tls_key`
is a common production mistake. The pipeline runs
`SSL_CTX_check_private_key` and returns -1 on mismatch;
`cmq_server_create` propagates this error.

## Test: `tls_e2e_handshake.cert_key_mismatch_rejected`

1. Generate two unrelated cert/key pairs (`cert.pem`/`key.pem`
   and `other.pem`/`other.key`).
2. Configure `cmq_server` with `tls_cert=cert.pem` + `tls_key=other.key`.
3. Assert `cmq_server_create` returns non-OK and the server
   pointer is NULL.

## What v0.5.60 ships

Just the test. No production change.
