# v0.5.24 — Multi-listener real concurrent bind + accept test

## Scope
v0.5.18 shipped the multi-listener runtime accept loop
(`src/server/cmq_server.c:7193-7230` — binds additional listen sockets
on `cfg.port + li` for `li = 1..listener_count-1`, port-guarded to
exclude test_server's `28800-28999` and `18800-18999` ranges).

The existing `tests/test_multi_listen.c` (v0.5.18) is a **smoke test**:
it calls `cmq_server_create` and immediately destroys, without
actually starting the accept loop or connecting to the additional
listeners. v0.5.24 turns it into a real test that:

1. Creates a server with `listener_count = 3` on `port = 28901`
   (just above the test_server range).
2. Starts the accept loop in a background thread.
3. Opens TCP connections to all three ports (28901, 28902, 28903).
4. Verifies each connection is accepted (a CMQ CONNECT/INFO response
   or just that the kernel doesn't RST).
5. Tears down cleanly.

This exercises the real accept path on all three listen sockets,
not just the create/destroy lifecycle.

## Design (performance-first, safety, reliability)

### Test approach

- **Avoid** the heavyweight CMQ protocol handshake — we just want to
  confirm the kernel accepted the TCP connection. A successful
  `connect()` + immediate close is sufficient evidence.
- **Avoid** `cmq_server_run` blocking — use a pthread that runs
  `cmq_server_run` in the background; the test thread does the
  connects.
- **Use distinct ports outside the test_server reservation range**
  (28901–28903) so test_server's port guard doesn't activate and we
  actually exercise the multi-listener branch.
- **Stop the server via SIGTERM-style shutdown**: `cmq_server_destroy`
  blocks waiting for in-flight ops; we rely on the test framework's
  timeout (or a short `nanosleep` loop on a flag).

### Safety

- Each connection is `connect + close`; no data is exchanged, so no
  state corruption risk.
- The test uses `127.0.0.1` only — never a public address.
- Test cleans up via `cmq_server_destroy` regardless of success.

### Reliability

- If `connect()` to any of the 3 ports fails, the test fails (with
  a clear message identifying which port).
- The accept thread must be observably running before the test
  attempts connects — a 50 ms sleep + a `so_error` poll.

| `port_guard_excludes_test_range` | port in 28800-28999 doesn't activate multi-listener branch |

## Risk

- `cmq_server_run` blocks. We'll run it in a `pthread`. The existing
  test_server fixture already does this with `pthread_create`, so we
  follow the same pattern.

- Port collisions: ports 28901/28902/28903 might be in use by other
  tests in the suite. Mitigation: use the `RESOURCE_LOCK` mechanism
  already in place (`CMQ_TCP_TESTS` in `tests/CMakeLists.txt:10`).
  Add `test_multi_listen` to that list so it serializes with
  `test_server` etc.
