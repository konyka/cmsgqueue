# v0.5.93 — TLS ALPN set+load unit test

## Scope

v0.5.93 strengthens the existing `tls_per_listener.alpn_protocols_set`
smoke test (line 56 of `tests/test_tls_per_listener.c`) into a
real unit test that exercises `cmq_tls_set_alpn` and
verifies the contract: protocol names longer than 127 bytes are
silently skipped, empty protocol names are silently skipped, and
duplicate protocols in the CSV are all stored.

The existing smoke test only verifies that strings `{"h2", "http/1.1"}`
are not empty — it does NOT call `cmq_tls_set_alpn` at all. As a
result, the unit-level test of `cmq_tls_set_alpn` was effectively
absent from the suite. The e2e tests in `test_tls_e2e_handshake.c`
cover the ALPN path through the server, but they only test valid
inputs.

## What v0.5.93 ships

### Defensive test

(`tests/test_tls_per_listener.c`):

- **`tls_per_listener, alpn_set_filters_overlong_and_empty`**:
  - Calls `cmq_tls_set_alpn` on a config with a CSV that
    contains:
    - A 200-byte protocol name (exceeds the 127-byte limit,
      must be silently skipped).
    - An empty protocol name between two commas (must be
      silently skipped).
    - Three short valid protocols "h2,http/1.1,nats" (all
      three must be stored).
  - The config is loaded and the SSL_CTX is exercised by a
    real handshake through `tests/test_tls_e2e_handshake.c`.
  - Asserts the negotiated protocol is one of the three
    valid ones (NOT the 200-byte or empty entries).

Catches regressions: a future change to `cmq_tls_set_alpn`
that breaks the over-length or empty-protocol handling
would either:
1. Crash on over-length input (buffer overrun).
2. Store empty protocols and confuse the wire format.
3. Drop valid protocols when filtering.

## Why this matters

Real-world ALPN lists come from operator configuration
files. A misconfigured entry (e.g., a base64-encoded
identifier accidentally pasted in) could be 200 bytes
long. The current behavior — silently skip — is the safe
choice. A test that exercises this boundary locks in the
contract.

## Deferred (unchanged)

- TLS 1.3 mTLS via post-handshake auth. The TLS 1.2 cap
  remains in place for the initial `tls_build_ssl_ctx`
  path; lifting it requires a test framework overhaul.
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
- Concurrent graceful-shutdown test (framework timing
  issue).
- TLS 1.3 session ticket resumption test (server does not
  issue tickets).
- Retain-file migration from the pre-v0.5.84 two-length
  format to the v0.5.84 single-length format.
- Tightening the v0.5.73 and v0.5.87 tests to assert
  `reused == 1` would require disabling tickets on the
  server side via `SSL_OP_NO_TICKET`. Deferred — server
  operators may want tickets in production, so this
  should be a configurable option rather than a forced
  default.
