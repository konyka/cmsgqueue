# v0.5.96 — Per-listener `tls_no_tickets` wiring

## Scope

v0.5.94 added the `tls_no_tickets` config option and wired it
into slot 0 only. The `cmq_listener.tls_no_tickets` struct
field was added for forward compatibility, but the per-listener
wiring loop (slots 1-3) never read it. Operators using the
multi-listener config to bind distinct ports/certs could not
disable tickets on a per-listener basis.

v0.5.96 closes this gap.

## What v0.5.96 ships

### Production fix (`src/server/cmq_server.c`)

- The per-listener block (line 7100-7141) reads
  `srv->config.listeners[li].tls_no_tickets` and applies
  `cmq_tls_set_no_tickets(srv->tls_config_slots[li], 1)`
  when set, mirroring the slot 0 wiring.

### Defensive test
(`tests/test_tls_e2e_handshake.c`):

- **`tls_e2e_handshake, three_listeners_per_listener_no_tickets`**:
  - Spin up 3 listeners via the existing `three_listeners`
    pattern. Each listener has its own cert.
  - Configure listener 1 with `tls_no_tickets = 1`,
    listeners 0 and 2 without.
  - Reach into each listener's slot via the test-only
    accessor and verify the `SSL_OP_NO_TICKET` flag.
  - Listener 1's slot has the flag; listeners 0 and 2 do
    not.

This locks in the per-listener field is honored.

## Why this matters

The per-listener TLS path (slots 1-3) is the production
configuration for any multi-listener deployment. Leaving
the `tls_no_tickets` field unwired means the documented
option silently no-ops on listeners 1-3, which is a real
correctness gap.
