# v0.5.89 — Consume spans (D1 follow-up)

## Scope
`KIND_CONSUME` exists on the ring and in OTLP encode, but
`handle_publish` only offers `KIND_PUBLISH`. This increment
offers one consume span after a successful local fanout.

## Design (performance-first, safety, reliability)

- One consume span per successful fanout, not per subscriber.
- Same 16-byte publisher `trace_id`.
- No subscribers / failed deliver: no consume span.
- `otel == NULL`: no-op (same as publish).
- Offer stays non-blocking; drop-newest unchanged.
