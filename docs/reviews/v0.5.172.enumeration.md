# v0.5.172 — verify CHECKSUM on RESPONSE

## Scope
REQUEST consumes `CMQ_FLAG_CHECKSUM` (v0.5.171).
The parser accepts the bit on RESPONSE, so the
trailing CRC32C was treated as body bytes — the
same silent interop class as COMPRESSED before
v0.5.99.

BATCH stays a later cut.

## Design (performance-first, safety, reliability)

- Reuse `cmq_checksum_consume`. 0 / omitted / empty
  flags keep `*len`. Mismatch fail closed.
- `handle_response` consumes after inflate, before
  inbox decrement / subject parse so a bad trailer
  does not drop `inbox_pending`.
- Uncompressed RESPONSE without the bit: one
  flag-bit compare.
