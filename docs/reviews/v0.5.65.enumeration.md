# v0.5.65 — JWKS oct-key cache (D3 phase 3)

## Scope
JWT verify uses one HMAC secret. This increment parses a
configured JWKS document (`jwks_json`) of `oct`/`HS256`
keys and selects by JWT `kid` on CONNECT.

HTTP JWKS fetch, RSA/EC, ES256, and nkey base32 stay deferred.

## Design (performance-first, safety, reliability)

- No `jwks_json`: existing HMAC / nkey paths unchanged.
- Parse once at config validate / server create (max 8 keys).
- Unknown `kid` fails closed (no fallback to the static secret).
- Missing `kid` may use `jwt_hmac_secret` when that is set.
- Document cap 4 KiB. `kty` must be `oct` when present.
