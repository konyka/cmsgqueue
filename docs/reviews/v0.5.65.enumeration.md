# v0.5.65 — mTLS multi-CA bundle defensive test

## Scope

Production mTLS deployments often need multiple CAs in the
trust bundle (e.g., during a CA migration, or when trusting
both a root CA and an intermediate CA). The simplest way to
configure this is to concatenate the PEM files into a single
file. OpenSSL 3.5's `SSL_CTX_load_verify_locations` only loads
the FIRST cert in a concatenated PEM file — a documented
limitation that's easy to miss.

This test locks in the documented behavior so future OpenSSL
upgrades don't silently change it (in either direction).

## Test: `tls_e2e_handshake.mtls_multi_ca_bundle`

1. Generate two CAs (`ca1`, `ca2`).
2. Sign a server cert with `ca1`.
3. Sign a good client with `ca1`, a bad client with `ca2`.
4. Concatenate `ca1.pem` + `ca2.pem` into a single bundle.
5. Configure server with `tls_ca=bundle.pem`.
6. Connect with the ca1-signed client → handshake succeeds.
7. Connect with the ca2-signed client → handshake fails (ca2
   isn't loaded because only the first cert in the bundle is
   used).
