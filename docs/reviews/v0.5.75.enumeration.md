# v0.5.75 — deferred (docs-only)

## Scope

v0.5.75 attempted two scopes:
1. **Concurrent graceful-TLS-shutdown test**: Two simultaneous
   TLS clients complete full handshakes, then the server stops.
   Both clients must observe `SSL_RECEIVED_SHUTDOWN` set. The
   test hung in the framework context because `SSL_read` blocks
   on a blocking fd while the server's close_notify propagation
   raced with worker shutdown. Solution attempt (non-blocking fd
   + poll with `POLLIN`) hit a similar hang because the server's
   BIO write requires `select(POLLOUT)` to retry, not just `POLLIN`.
   This needs a second-level poll loop in the test harness.

2. **Invalid CA bundle rejection test**: mTLS client with a cert
   signed by a CA *not* in the server's `tls_ca` bundle must be
   rejected. The test failed at cert-generation step because
   OpenSSL's serial database (`*.srl`) had stale state from prior
   test runs.

Both attempts stalled on infrastructure issues (test framework
timing, OpenSSL state). The single-client graceful_shutdown
test (v0.5.72) and cross-CA rejection test (v0.5.56) already
cover the core path.

## What v0.5.75 ships

A docs-only release. No production change. No test change.

## Deferred to v0.5.76+

- Concurrent graceful-shutdown test (per-client thread with
  `POLLOUT` poll loop for BIO write retries).
- Invalid CA bundle rejection test (clean OpenSSL state between
  test cases, e.g. via `gnutls-cli --ca-cert` or mocked cert).
- TLS 1.3 session ticket resumption test (server doesn't issue
  tickets — `has_ticket==0`).
- TLS 1.3 mTLS via post-handshake auth (v0.5.48/v0.5.49 race).
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
