# v0.5.54 — MQTT QoS 1 outbound inflight

## Scope
Inbound PUBACK / PUBREC already exist. Subscribers still receive
QoS 0 only (retain path `0x30`) and there is no window, so a
granted QoS 1 SUBSCRIBE cannot complete the handshake.

This increment adds a **fixed 16-slot** inflight window per live
session, encodes outbound QoS 1 PUBLISH with a packet id, acks on
PUBACK, and fans MQTT PUBLISH out to matching local subscribers.

D1–D5 stay deferred. Outbound QoS 2 is not granted today (cap 1).

## Design (performance-first, safety, reliability)

- Slots are inline (no malloc on offer). Payload cap 1024;
  larger values fall back to QoS 0 so they still deliver.
- Window full: skip that dest (publisher is not blocked).
- Packet id never 0; wrap skips 0.
- Unknown / duplicate PUBACK is a no-op.
- Fanout copies encoded packets under the session lock, then
  `send()` after unlock.
- Topic match uses `cmq_mqtt_topic_match`.
