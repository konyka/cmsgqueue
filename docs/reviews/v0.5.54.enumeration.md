# v0.5.54 — CRL with non-revoked client defensive test

## Scope

The v0.5.47 test (`mtls_revoked_client_rejected`) covers the
case where a client's cert IS revoked by the CRL. v0.5.54
covers the more common case: a CRL is configured but the
connecting client's cert is NOT in the CRL.

This guards against future regressions in the CRL
scope-matching code where valid clients are falsely rejected
because of issues like the OpenSSL #23325 scope-matching bug
(certs without CDP rejected with
`X509_V_ERR_DIFFERENT_CRL_SCOPE` 44).

## Test: `tls_e2e_handshake.mtls_crl_not_revoked_accepted`

1. Generate a CA + server cert + two client certs (both with
   CDP extensions pointing at the CRL file).
2. Three-step CRL generation: empty → revoke the second
   client (other_client) → re-emit. **The first client
   (our_client) is NOT revoked.**
3. Configure `cmq_server` with `tls_verify_peer=1`,
   `tls_ca=CA`, `tls_crl=CRL`.
4. Connect with the non-revoked client.
5. Assert the handshake succeeds.

## What v0.5.54 ships

Just the test. No production change.
