# v0.5.91 — TLS 1.2 session resumption correctness

## Scope

v0.5.91 tightens the existing `tls_session_resumption` test
(v0.5.73) and the v0.5.87 reload-survives test by adding a
new defensive test that pins the client to TLS 1.2 and
asserts `SSL_session_reused` returns 1 (was 0 in TLS 1.3
because OpenSSL 3.x defaults to ticket-based resumption
there).

The investigation behind this round:

- TLS 1.3 uses session tickets by default. Tickets are
  stored and exchanged outside OpenSSL's
  `new_cb`/`get_cb` mechanism. The server's `get_cb` is
  never consulted in TLS 1.3 by default.
- TLS 1.2 with `SSL_OP_NO_TICKET` not set still works
  with ID-based resumption, provided the server's
  `session_id_context` matches (already set in
  `tls_build_ssl_ctx`).
- The existing v0.5.73 test ran the client without a
  version pin, which let OpenSSL default to TLS 1.3.
  That test asserted `reused == 0 || reused == 1`,
  accepting either outcome, which masked the real cache
  hit behavior.
- A standalone TLS 1.2 client with the production
  certificate correctly observes `reused == 1` on the
  second connection.

## What v0.5.91 ships

### Defensive test
(`tests/test_tls_e2e_handshake.c`):

- **`tls_e2e_handshake, tls12_session_resumption`**:
  - Server: TLS on port 25587.
  - Client: TLS 1.2 ONLY (`min/max_proto_version =
    TLS1_2_VERSION`).
  - Connection 1: full handshake. Capture the session.
    Verify `SSL_version(cssl) == 0x0303` (TLS 1.2) and
    `SSL_session_reused(cssl) == 0`.
  - Connection 2: present the captured session.
  - Assert `SSL_session_reused(cssl2) == 1`. Without
    `session_id_context`, server-side session caching,
    `new_cb`/`get_cb` wiring, or `gen_session_id`, this
    test fails.

## Why this matters

This test locks in three things:

1. TLS 1.2 ID-based resumption works on the initial
   SSL_CTX (the `tls_build_ssl_ctx` wiring is correct).
2. The `session_id_context` is preserved across handshakes
   so the server accepts the client's session ID.
3. The `gen_session_id` callback produces IDs the client
   accepts back as session identifiers.

The existing `tls_session_resumption` test (v0.5.73) and
the v0.5.87 reload-survives test are weakened by
TLS 1.3 ticket-based resumption. The new v0.5.91 test
isolates the ID-based path.

## Deferred (unchanged)

- TLS 1.3 mTLS via post-handshake auth. The TLS 1.2 cap
  remains in place for the initial `tls_build_ssl_ctx`
  path; lifting it requires a test framework overhaul.
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
- Concurrent graceful-shutdown test (framework timing
  issue).
- TLS 1.3 session ticket resumption test (server does not
  issue tickets).
- Retain-file migration from the pre-v0.5.84 two-length
  format to the v0.5.84 single-length format.
- Tightening the v0.5.73 and v0.5.87 tests to assert
  `reused == 1` would require disabling tickets on the
  server side via `SSL_OP_NO_TICKET`. Deferred — server
  operators may want tickets in production, so this
  should be a configurable option rather than a forced
  default.
