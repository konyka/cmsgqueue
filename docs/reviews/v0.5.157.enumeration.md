# v0.5.157 — attach subscription persist on reload

## Scope
Create opens `cmq-subs.wal` next to the WAL.
v0.5.144/150 only opened and loaded it inside the
filestore-attach block, so a live filestore whose
persist handle was still NULL never got F18.

## Design (performance-first, safety, reliability)

- `cmq_sublist_persist_reload_attach`: empty/omitted
  keeps off. Existing `*p` is left alone (no remount).
- `..` / `\` fail closed. `fopen` miss keeps off
  (same best-effort as create).
- After attach, load once (v0.5.150). WAL message
  replay stays create-time. Live `persist_dir` is
  not rewritten (no remount).
