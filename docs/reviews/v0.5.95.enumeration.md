# v0.5.95 — TLS session cache initialization fix

## Scope

v0.5.95 fixes a real production bug discovered during the
v0.5.94 investigation: `cmq_tls_session_cache_init` was
defined but never called anywhere in the production code.
As a result, `cfg->session_cache_state` stayed NULL throughout
the config lifecycle, `cmq_tls_session_cache_insert` always
returned -1, and the per-config session cache never worked.

The v0.5.91 tls12_session_resumption test passed only
because OpenSSL's INTERNAL fallback cache was serving the
resumption, despite `SSL_SESS_CACHE_NO_INTERNAL` being set.
This was a fragile state: the production code was a no-op
cache with an inconsistent OpenSSL fallback.

## What v0.5.95 ships

### Production fix (`src/enterprise/cmq_tls.c`)

- **`cmq_tls_load`** now calls `cmq_tls_session_cache_init`
  after `tls_build_ssl_ctx` succeeds. The cache is
  per-config, initialized once at load time, and used by
  both `cmq_tls_sess_new_cb` (insert) and
  `cmq_tls_sess_get_cb` (lookup). The init allocates the
  bounded LRU hash table and a mutex.

### Defensive test
(`tests/test_tls_e2e_handshake.c`):

- **`tls_e2e_handshake, tls12_session_resumption_via_cache`**:
  - Server on port 25591 (TLS 1.2 pin on client).
  - Connection 1: full handshake, capture session.
  - Connection 2: present captured session.
  - Assert `reused == 1`. The fix now makes the cache work
    end-to-end.

This replaces the v0.5.91 test's "accept either 0 or 1"
pattern with a strict assertion that the cache actually
serves the lookup. The v0.5.91 test stays as-is to maintain
backward compatibility.

## Why this matters

Operators using TLS session resumption for performance
rely on the cache. Before this fix, OpenSSL's internal
fallback was handling resumption but with NO application-
level control: clients were tied to a single OpenSSL
instance's internal table. With the per-config cache active:
- Operators can inspect cache state (size, eviction, etc).
- The cache is bounded (1024 entries by
  `CMQ_TLS_SESSION_CACHE_MAX`).
- The cache works across `cmq_tls_reload` (the cache state
  is on the config, not the CTX).
