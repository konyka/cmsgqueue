# v0.6.0 — TLS reload context lifetime regression coverage

## Scope

The v0.5.x TLS reload path already contains the v0.5.4
`SSL_CTX_up_ref` lifetime fix: each `SSL_new(cfg->ssl_ctx)`
holds an OpenSSL context reference, and reload frees the old
context only after swapping the new one in. v0.6.0 starts the
next major line by exercising that contract through a real
active TLS session rather than a synthetic refcount smoke test.

## What v0.6.0 ships

- **`tests/test_tls_e2e_handshake.c::reload_with_active_tls_session`**:
  - Start a TLS listener and complete a client handshake.
  - Keep the active client connection alive.
  - Call `cmq_tls_reload` while that TLS session is active.
  - Complete a new handshake after the reload.
  - Close the original connection and assert the process
    remains stable.

This proves the old SSL_CTX remains valid for the active
`SSL*` after the reload while new sessions use the replacement
context. It is a real-listener regression test for the existing
UAF/lifetime design, not a duplicate production change.

## Deferred
