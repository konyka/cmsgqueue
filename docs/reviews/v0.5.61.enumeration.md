# v0.5.61 — OpenTelemetry span ring (D1 phase 1)

## Scope
Span IDs exist (`trace_hex`). There is no exporter and no
queue for spans. D1's design is a sidecar + bounded ring,
never I/O on PUBLISH.

This increment adds `cmq_otel`: a 256-slot MPSC ring, drop
newest on overflow, a drain thread that calls an export
hook. No payload bodies. gRPC/OTLP stays deferred.

## Design (performance-first, safety, reliability)

- `offer` is one fetch-add + store. Full ring increments
  `dropped` and returns 1 (newest lost).
- Export runs on the sidecar only.
- Default export is a counter (no I/O, no bodies).
- Server offers a PUBLISH span after validation; missing
  otel is a NULL check.
