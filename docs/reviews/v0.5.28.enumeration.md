# v0.5.28 — Real end-to-end TLS handshake test

## Scope
v0.5.27 wired the session resumption cache into OpenSSL's handshake
lifecycle but only verified the **structural** wiring (cache mode set,
callbacks registered, app_data linked). The v0.5.27 honest caveat
noted: no test actually completes a TLS handshake and observes the
cache growing.

v0.5.28 closes that gap. The test does a real TLS handshake between
two sockets on `127.0.0.1` (one server, one client) using the
production `cfg->ssl_ctx` (via the v0.5.27 test-only accessor) and
asserts:

1. The handshake completes.
2. The cache size grows from 0 to >= 1 (proving the new_session
   callback fired and inserted).
3. A second handshake with the same client SSL gets resumed (cache
   size still >= 1; SSL_session_reused returns 1 on the client).

## Design (performance-first, safety, reliability)

### Test approach

- **Raw OpenSSL for both sides.** The cmq_tls API forces non-blocking
  fds, which require an event loop to drive from a test. Driving an
  event loop in a unit test is brittle (different fd-readiness
  policies, CPU spinning risks). Raw OpenSSL with `select()` gives a
  simple, deterministic test driver.
- **Production SSL_CTX for the server side.** The test uses
  `cmq_tls_get_ssl_ctx_for_test()` to get the production
  `cfg->ssl_ctx` (with v0.5.27 callbacks wired). The new_session
  callback fires naturally; we don't have to manually invoke it.
- **Fresh client SSL_CTX.** Different from server (server CTX is
  configured as a server, which would cause OpenSSL errors on the
  client side). Load the server's self-signed cert as a trust anchor
  on the client.
- **Two-phase test:**
  - Phase 1: full handshake → cache size == 1.
  - Phase 2: same client SSL reconnects with cached session → cache
    size still >= 1 AND `SSL_session_reused(client_ssl) == 1`.

### Safety

- Self-signed cert (test-only).
- Test binds to `127.0.0.1` only.
- fds explicitly closed in teardown.
- 5-second overall timeout via `select()` deadline.

### Reliability

- select() with 100ms timeout per iteration. The loop terminates
  when both handshakes complete (rc_s == 1 && rc_c == 1) or after a
  generous iteration cap.
- If a handshake error occurs, dump_err() prints the OpenSSL error
  for diagnosis.
- Test is deterministic: no time-of-day dependencies, no shared
  state across tests (each test creates its own config + cert).

## Risk
- v0.5.27 prototyped this and the test hung because the test code
  reused the server's `SSL_CTX` for the client (causing OpenSSL's
  "called a function you should not call"). v0.5.28 must use a
  **separate client CTX** — the test approach in the prototype
  already does this; we just need to commit the test code.
- OpenSSL session resumption with self-signed certs in TLS 1.3 may
  not work if the server's session_lifetime is too short or if the
  client doesn't request a session. We may need to enable
  `SSL_OP_NO_TICKET` or set explicit session lifetime. The
  v0.5.27 prototype confirmed cache size grew on first handshake,
  so the resumption part of the test is incremental value.
