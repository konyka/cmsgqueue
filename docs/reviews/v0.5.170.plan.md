# v0.5.170 — wire WS permessage-deflate on upgrade

## Goal

The live WS handshake accepts RFC 7692 when the client
offers it, and send/recv compress data frames. Omitted
extensions keep the uncompressed path.

## Performance

No extension header: one scan then the existing send
path. Negotiated send: one `deflateInit2` / `Z_SYNC_FLUSH`
per BINARY frame. Recv inflate only when RSV1 is set.

## Security

Unsupported extension parameters fail closed. RSV2/3
and RSV1 on control frames stay rejected. Inflate
errors tear down the connection.
