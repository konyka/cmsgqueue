# v0.5.55 — missing CRL file path defensive test

## Scope

The v0.5.47 CRL pipeline uses `BIO_new_file` which returns
`NULL` if the file doesn't exist. The production code's
existing fallback: when `BIO_new_file` returns NULL, the CRL
is silently skipped. The server starts up, doesn't crash,
and client cert verification runs without CRL enforcement.

This is a **fail-open** policy (don't reject valid clients
when the CRL is misconfigured). It has security tradeoffs:
a misconfigured `tls_crl` path means no CRL enforcement.
The test documents this behavior so future "helpful"
changes that flip the policy to fail-closed would be
intentional, not accidental.

## Test: `tls_e2e_handshake.mtls_missing_crl_file_path`

1. Generate a CA + server cert + client cert (no CRL needed).
2. Configure `cmq_server` with `tls_verify_peer=1`,
   `tls_ca=CA`, `tls_crl="/tmp/cmq-test-no-such-crl.pem"`
   (nonexistent).
3. Server creation must succeed (no crash).
4. Connect with the valid client cert.
5. Assert the handshake succeeds (CRL silently skipped).
