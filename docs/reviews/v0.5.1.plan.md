- P1 mTLS in `cmq_tls.c`, P1 F17 in `cmq_route.c`, and P1 reload UAF in the reload region of `cmq_server.c` can execute concurrently.

## 5. Verification Gates

### TDD and Atomic Commit Strategy

Every P-item follows an independently reviewable delivery chain:

1. **Doc-first:** Define `## Design`, exact test names, expected RED cause, security/performance constraints, limitations, and verification commands.
2. **RED:** Add the smallest test exposing the defect. Record that it fails for the intended reason before production code changes.
3. **GREEN:** Add the smallest implementation that passes the focused test and complete default suite.
4. **Refactor:** Optional separate commit with no behavioral or acceptance-criteria changes.
5. **Closeout:** Fill measured `## Verification gates`, update `CHANGELOG.md`, and include before/after output for performance work.

Commit subjects use `<type>(P#): <imperative outcome>`. Do not combine unrelated P-items. New tests must land before implementation. P9 is split into bootstrap and consolidation commits. Reload UAF is the sole deterministic unit-RED exception: its test-first artifact is the TSAN reload-stress harness plus structural lifetime review.

### Default Build and CTest

```bash
cmake --build build -j
cd build && ctest --no-tests=error --output-on-failure -j1
```

- CMake build exits 0.
- All 55 baseline tests remain green, plus every new test; discovered test count must not decrease.
- Each new test first fails for its documented reason.
- Focused tests support diagnosis but never replace complete `ctest -j1`.
- `tests/test_bench_regression.c` remains excluded unless `CMQ_ENABLE_BENCH=1`.
- Every atomic implementation commit must pass the focused test, default CTest, and applicable sanitizer gate before merge.

### Benchmark Gate

```bash
cmake -S . -B build-bench \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMQ_ENABLE_BENCH=1
cmake --build build-bench -j
./build-bench/examples/benchmark -c 10 -n 10000 -t 1
```

- Record the unchanged-HEAD baseline before implementation, including CPU, compiler, flags, persistence mode, warm-up, sample count, and repetitions.
- Require at least 30K msg/s, p99 publish latency no greater than 60 µs, and `stat_messages_dropped == 0`.
- Require p50, p99, and msg/s to remain within 5% of the recorded baseline unless the item intentionally improves that metric.
- Treat the approximately 0.029 ms HEAD average as a reference, not a substitute for controlled baseline data.
- F17 requires TLS handshake p50 no greater than 5 ms and route-worker CPU delta no greater than 5% of wall time over 10 seconds at 10K msg/s.
- P3/P7 recovery must complete within 10 ms per 100K subscriptions.
- P2 must improve synchronous-WAL performance while preserving payload bytes, sequence order, bounded backpressure, explicit sync, destroy drain, and the existing batched-`fflush` durability contract.
- Performance commits include before/after benchmark output in the commit body.

## 6. Risk Register

| Item | Risk | Mitigation and TDD evidence |
|---|---|---|
| **P0** | WAL replay drops persisted messages on every restart. A naive epoch fix re-appends records, causing duplicate delivery and unbounded growth. | Land first. Require `persist_unit.replay_restores_messages` and `perf.wal_replay_idempotent`; assert unchanged WAL length after repeated restarts. |
| **P1 reload UAF** | Workers can read freed ACL/blocklist objects. The race is not deterministically unit-testable. | Use atomic generation swap with deferred reclamation. Require structural lifetime review, reload stress under TSAN, and reload-path ASAN smoke. |
| **P1 subject_rl/quota** | Linked-list races can corrupt memory or bypass limits. A mutex would regress the publish hot path. | Use bounded fixed-slot atomic tables, never a mutex. Require concurrent no-bypass RED tests, TSAN, and contention benchmarks. |
| **P1 BATCH** | BATCH entries can evade ACL/quota/rate checks; rejected publishes can enter the WAL. | Complete every admission check before persistence or delivery. Test BATCH rejection and verify rejected records remain absent after restart. |
| **P1 mTLS** | Production verification is unreachable; premature `SSL_CTX` reclamation can UAF active sessions and obstruct P5. | Define generation ownership in ADR 0010. Test trusted/untrusted CA, missing certificate, verify-off behavior, reload, and session drain. |
| **P1 F17** | Blocking TLS handshake, reads, or partial writes can hang route workers. | Use nonblocking poll deadlines and partial-write handling. Require stalled-peer RED tests, handshake p50 limit, and route-worker CPU gate. |
| **P2** | Async WAL buffering can reorder or lose acknowledged data or silently change durability semantics. | Preserve bounded backpressure, sequence order, explicit sync, destroy drain, and batched-`fflush` contract. Require byte-for-byte equivalence tests. |
| **P3** | Incorrect startup order can replay publishes before subscriptions load or resurrect unsubscribed state. | Load subscription state before publish replay. Test both SUB and UNSUB across restart. |
| **P4** | The MQTT listener expands parser, allocation, and state-machine attack surfaces. | Enforce packet/session bounds and deterministic cleanup. Require seven RED scenarios, MQTT fuzzing, and ASAN. |
| **P5** | Per-listener context reload can disconnect clients or free contexts still used by sessions. | Reuse P1 mTLS generation ownership. Require distinct-context, ALPN, and reload-without-disconnect tests. |
| **P6** | Rotation/open/write failures can silently erase audit evidence. | Retain a synchronized stream, report failures, and test rotation plus post-rotation writes under ASAN. |
| **P7** | Parallel replay can produce nondeterministic state or violate sequence ordering. | Use stable partitions and preserve order within each partition. Compare repeated runs and join workers before accepting clients. |

## 8. Stop Conditions

Stop the affected track and ask the lead before continuing if:

- A required RED test cannot be written, does not fail, or fails for a reason other than the documented defect.
- Production code is proposed before its RED test lands and demonstrates the expected failure.
- A default test regresses, disappears, repeatedly flakes, or discovery falls below 55 baseline tests plus additions.
- TSAN reports a new race, including an unrelated race newly reached by the workload.
- ASAN or UBSAN reports any error on a changed or newly exercised path.
- A benchmark regresses by more than 10%.
- A benchmark regresses by 5-10% and controlled reruns cannot attribute the result to measurement noise; recorded lead approval is required.
- P2 cannot preserve ordered batched `fflush`, bounded backpressure, explicit sync, or destroy-drain behavior.
- Subject-rate or quota work requires a mutex, unbounded probing, or undocumented fail-closed semantics.
- Reload or TLS work would reclaim an object or `SSL_CTX` still reachable by an active reader or session.
- P3 cannot establish deterministic subscription-load-before-publish-replay ordering.
- P7 cannot prove deterministic replay or meet 10 ms per 100K subscriptions under controlled measurement.
- F17 cannot bound handshake, read, or write waits, or cannot meet its handshake and route-worker CPU budgets.
- MQTT implementation requires behavior outside the agreed P4 or P8 protocol scope.
- MQTT fuzzing reveals a defect that requires a new architectural item rather than a local correction.
- F7 hardening flags, separate sanitizer builds, or default benchmark exclusion cannot be preserved.
- A parallel track needs uncoordinated changes to files or a `cmq_server.c` region reserved by another track.
- An atomic commit would mix unrelated P-items or combine RED and GREEN without preserving observable failure evidence.
- A required closeout lacks measured verification results, applicable sanitizer evidence, or a `CHANGELOG.md` update.
- Any proposed change creates a fifteenth P-item; stop and submit it to a new adversarial round instead of silently expanding the v0.5.1 scope.
