# v0.5.83 — ALPN no-overlap handshake rejection (defensive test)

## Scope

v0.5.82 added a default ALPN select callback that picks the
first server protocol also in the client's list, returning
`SSL_TLSEXT_ERR_ALERT_FATAL` on no overlap. v0.5.83 locks
in the failure path with a defensive test.

The callback contract:

- **Overlap exists** → callback returns the first server
  protocol that the client also offered; the server
  includes that protocol in the ServerHello's ALPN
  extension. (v0.5.82 test `alpn_negotiated_on_real_listener`.)
- **No overlap** → callback returns
  `SSL_TLSEXT_ERR_ALERT_FATAL`; the server sends a fatal
  `no_application_protocol` alert and the handshake fails.
  (v0.5.83 NEW test.)
- **Server has no ALPN configured** → callback is not
  installed; the server does not send an ALPN extension.
  (Already covered by tests 1-30 that don't configure ALPN.)

## What v0.5.83 ships

- **Defensive test**
  (`tests/test_tls_e2e_handshake.c::alpn_no_overlap_rejected`):
  - Spins up `cmq_server` with TLS enabled on port 25580.
  - Configures server with ALPN "h2,nats" via
    `cmq_tls_set_alpn` + `cmq_tls_reload`.
  - Connects a TLS client with ALPN "spdy/3,http/1.1" (no
    overlap with the server's list).
  - Asserts the handshake fails (rc != 1). The server's
    select callback should return NOACK, which translates
    to a fatal `no_application_protocol` alert in TLS 1.2
    or `SSL_AD_UNRECOGNIZED_NAME` in TLS 1.3.
- No production change.
- No test framework change.
- Bench: unchanged.
- CHANGELOG + tag + push.

## Why this matters

The v0.5.82 callback was the most subtle part of the
ALPN fix: it had to pick a protocol from the intersection
of two lists, and on no overlap return a fatal alert. The
positive case is already covered by
`alpn_negotiated_on_real_listener`. The negative case is
not — without v0.5.83, a future change that "softens" the
callback (e.g. returns `SSL_TLSEXT_ERR_NOACK` to allow the
handshake to proceed without ALPN) would silently change
the user-facing contract.
