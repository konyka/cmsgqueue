# v0.5.83 — TLS-wrapped h2 I/O (D2 phase 7)

## Scope
`h2_port` plus ALPN `h2` are live, but the h2 fd still
speaks prior-knowledge plaintext. This increment wraps
accept-path bytes in TLS when a TLS config is supplied.

## Design (performance-first, safety, reliability)

- `cmq_h2_session` I/O is abstracted (fd or TLS session).
- `cmq_h2_session_tls` / `cmq_h2_accept_tls` handshake
  then run the same preface/SETTINGS/POST machine.
- No TLS config: existing plaintext accept is unchanged.
- Server `cmq_server_h2_accept` uses TLS when slot 0 is
  configured. Handshake stays off PUBLISH.
- 200 ms I/O cap unchanged. Loopback bind only.
