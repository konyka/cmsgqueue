# v0.5.35 — Remove semantically-wrong bridge wiring

## Scope
v0.5.34 fixed the double-free in `cmq_mqtt_bridge_relay` (the relay
was freeing a payload that the sublist already owned). The root
cause: `cmq_server_create` wires the bridge relay to call
`cmq_sublist_insert`, which is the **subscription registry** API
(`subs[]` storage in trie nodes), not a publish API.

So the bridge is effectively doing nothing useful (it stores the
payload pointer as if it were a subscriber, where it will never
match a subject pattern — pub/sub matching is keyed by trie nodes
with `subs[]`, not by stored payloads).

v0.5.35 takes the pragmatic step: **revert the production wiring
to the no-op default**, document why, and verify all tests still
pass. The proper "publish into the sublist" path requires a real
publish helper (`cmq_server_publish`) that does the match +
fanout. Building that is M+ scope and deferred to v0.6.

## Design

### Change

In `cmq_server.c:6867`, replace:

```c
cmq_mqtt_register_sublist_insert((cmq_sublist_insert_fn)cmq_sublist_insert,
                                   srv->sublist);
```

with:

```c
/* v0.5.35: leave the relay's insert fn as the default no-op
 * (relay_insert_cb). The bridge relay pushes MQTT PUBLISH topics
 * to the bridge queue, but with no insert fn the relay's payload
 * pointers correctly land in the freelist (per the v0.5.34 fix)
 * and no sublist subscription is created. A proper publish path
 * that fans payloads out to subscribers is v0.6 work. */
(void)0;  /* explicit no-op */
```

Effectively: don't call `cmq_mqtt_register_sublist_insert` at all.
The default `relay_insert_cb` (no-op) is already in place.

### Safety

- No double-free. Without `g_relay_insert_fn` being
  `cmq_sublist_insert`, the v0.5.34 fix path is now the only path
  used in production: payloads go to the freelist (capped at 64).
- No semantic change to subscription handling — the cmq sublist
  is still populated by `cmq_sublist_insert` from the SUB opcode,
  not from the bridge.
- The bridge relay still consumes MQTT PUBLISH frames from
  `g_mqtt_bridge_*` and recycles their payloads. The fix is
  minimal: just don't pretend to publish.

### Tests

- `tests/test_mqtt_bridge_freelist_load.c:real_load_drains_to_freelist`
  already exercises the no-op path. After the wiring revert, it
  becomes the production behavior — the test passes
  without modification.
- Add a new test that verifies the sublist count is NOT bumped
  by bridge activity (proving the wiring doesn't accidentally
  insert subscriptions).

### Why this is honest

The bridge's purpose is "MQTT PUBLISH → cmq fanout". With the
wiring reverted, the bridge is "MQTT PUBLISH → recycle buffer".
The publish fanout isn't implemented. That's a v0.6 scope.

We document this limitation rather than ship incorrect behavior.
