# v0.5.26 — Wire cmq_mqtt_topic_match into the retained-dispatch loop

## Scope
v0.5.25 extracted the MQTT topic matcher into `cmq_mqtt_topic_match()`,
but the SUBSCRIBE-dispatch loop still uses the inline `+`-only logic.
This round wires the new function in, giving the dispatch path `#`
support for free.

## Design

### Code change
`src/enterprise/cmq_mqtt_server.c:682-707` currently:
1. Triggers only when `last_topic` contains `+`.
2. Has an inline per-retained-entry match loop that handles `+` only.

Replace with:
1. Trigger when `last_topic` contains `+` OR `#`.
2. Call `cmq_mqtt_topic_match(last_topic, g_mqtt_retained[ri].topic)`
   per entry. Same iteration; same lock-then-copy-then-release flow.

Net diff: ~10 lines. The existing copy-and-emit block at lines 712-744
stays unchanged.

### Safety
- `cmq_mqtt_topic_match` returns -1 only on invalid pattern; that means
  `last_topic` itself was malformed. In that case, no retained entry
  matches (treat as no-match, identical to current `+`-only path which
  also rejects malformed patterns). No new failure mode.

### Reliability
- Behavior change: retained dispatch now matches `#` wildcards in
  SUBSCRIBE filters. This is a strict superset of the v0.5.25
  behavior — clients that don't use `#` see identical results.
