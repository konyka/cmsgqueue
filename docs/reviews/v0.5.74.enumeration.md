# v0.5.74 — deferred (docs-only)

## Scope

v0.5.74 attempted to add a defensive test validating the
v0.5.72 graceful-TLS-shutdown fix under concurrent load
(two simultaneous TLS clients completing handshakes, then
server stop). The test attempt hung in the framework
context — the test framework's stdout was suppressed and
the second client's SSL_read blocked indefinitely because
the server's close_notify was racy against the workers
shutdown.

The single-client graceful shutdown test (v0.5.72) already
covers the core path. A truly bulletproof concurrent test
requires either: (a) per-client SSL_read with poll() + SO_RCVTIMEO
on the raw fd before entering SSL_read, or (b) spawning
each client's handshake + drain in a dedicated thread
before calling cmq_server_stop.

Both approaches are > 50 lines of test code. To preserve
the v0.5.x pattern of small defensive tests, v0.5.74 ships
docs-only.

## What v0.5.74 ships

A docs-only release. No production change. No test change.

## Deferred to v0.5.75+

- Concurrent graceful-shutdown test (separate-thread approach
  with poll() bounded SSL_read).
- TLS 1.3 session ticket resumption test (blocked by TLS 1.3
  client requiring server-side ticket issuance, which the
  current server doesn't do).
- TLS 1.3 mTLS via post-handshake auth (v0.5.48/v0.5.49 race).
- Per-listener `accept_thread_func` refactor (already on
  remote workstream as v0.5.42).
