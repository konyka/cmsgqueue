# v0.5.98 — Per-listener invalid-credentials fallback

## Scope

v0.5.98 covers the documented per-listener TLS fallback path
when a listener's certificate/key pair fails validation.
The server should continue starting with the global slot 0 TLS
context while discarding only the invalid listener slot.

## What v0.5.98 ships

- **`tests/test_tls_e2e_handshake.c::tls_slot3_invalid_credentials_fallback`**:
  - Configure valid global TLS credentials.
  - Configure four listener slots, with slot 3 using a
    mismatched certificate/key pair.
  - Assert `cmq_server_create` succeeds.
  - Assert slot 3 is discarded while slot 0 remains usable.
  - Start the listener and complete a real handshake through
    slot 0.


## Coverage by concern

- 44 TLS e2e tests after v0.5.98.
- Invalid per-listener startup credentials now have direct
  fallback coverage.

## Deferred

- TLS 1.3 mTLS post-handshake auth.
- TLS 1.3 session ticket issuance and rotation.
- Retain-file migration from the pre-v0.5.84 format.
