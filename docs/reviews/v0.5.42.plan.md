# v0.5.42 — Aux accept thread admits (R1)

## Goal

A `num_threads > 1` server must not drop connections on the second
accept thread. Admission uses the same gates as the main acceptor.

## Why this first

R1 is a live reliability bug: the thread is spawned, then either
closes fds or exits on `running=1`. Operators who set `threads=4`
believe accept is parallel; extra-listener races during startup
drop clients. R2–R7 are features; this is a correctness hole.

## Performance budget

- Uncompressed publish path: untouched.
- Accept: one extra `epoll_wait` thread only when `nthreads > 1`.
- Per-admit cost identical to `accept_cb` (shared helper).
- Floor unchanged (≥ 25 000 msg/s).

## Security

- No new listen surface; same `max_clients` / rate-limit / TLS.
- Fail-closed on drain: close, do not admit.

## Stop

- `stat_accept_aux >= 1` under a 32-connect burst with
  `num_threads=2`.
- CONNECT/CONNACK succeeds on an aux-admitted fd.
- Push `v0.5.42` to `origin`.
