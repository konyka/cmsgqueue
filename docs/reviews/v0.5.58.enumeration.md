# v0.5.58 — mTLS forces TLS 1.2 defensive test

## Scope

v0.5.46 added a TLS 1.2 cap to the SSL_CTX when `verify_peer=1`
because OpenSSL 3.5 + TLS 1.3 silently bypasses
`SSL_VERIFY_FAIL_IF_NO_PEER_CERT`. This test locks in that
design decision: a TLS 1.3-only client must fail to handshake
with an mTLS-enabled server.

## Test: `tls_e2e_handshake.mtls_forces_tls12`

1. Generate a CA + server cert + client cert.
2. Configure `cmq_server` with `tls_verify_peer=1` (triggers
   the cap).
3. Connect with a TLS 1.3-only client (`min=max=TLS1_3_VERSION`).
4. Assert the handshake fails.

## What v0.5.58 ships

Just the test. No production change.

## Why this test matters

If a future refactor "fixes" TLS 1.3 mTLS (e.g., resolves the
v0.5.48/v0.5.49 race) and removes the v0.5.46 cap, this test
fails — forcing the author to update the test along with the
fix. The test serves as a tripwire for that design boundary.
