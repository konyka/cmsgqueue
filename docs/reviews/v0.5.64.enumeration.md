# v0.5.64 — mTLS self-signed CA defensive test

## Scope

The simplest self-signed mTLS deployment: generate one cert,
use it as both server cert and CA bundle. Tests 4 and 8 use
CA-signed chains; test 18 verifies the degenerate self-signed-
only case works correctly with the same file used as both
server cert and CA bundle.

## Test: `tls_e2e_handshake.mtls_self_signed_ca`

1. Generate two self-signed certs (server + client).
2. Configure server with `tls_cert=cert.pem`, `tls_ca=cert.pem`
   (same file used as both server cert AND CA bundle).
3. Connect with the client cert (signed by a DIFFERENT self-signed
   CA).
4. Assert the server REJECTS the client cert (different CA,
   even though tls_ca file exists).

This verifies that using the same file for cert and CA bundle
doesn't accidentally widen the trust.
