**Scope.** Items deferred from v0.5.2 (which shipped 14/14 P-items from the
v0.5.2 enumeration) plus any new gaps found at HEAD (v0.5.2 tagged).

## Sources

- `docs/reviews/v0.5.2.enumeration.md` — adversarial enumeration.
  Note: 13 P-items were planned, but v0.5.2 also split BATCH/PUBLISH-
  sublist bridge into partial (P1 SUBSCRIBE/SUBACK) + deferred (P1

## P1 — F19b FULL MQTT→cmq_sublist bridge

- **gap** → `src/enterprise/cmq_mqtt_server.c:357` (PUBLISH stores
  retained payload only; no insertion into `srv->sublist`) + `:114`-
  `:147` (`cmq_mqtt_server_start_listener(struct cmq_server *)` is
  given the server, but the PUBLISH handler does not call
  `cmq_sublist_insert`).
- **impact**: server-side MQTT broker is functionally incomplete —
  no SUBSCRIBE-pattern matching, no MESSAGE delivery to cmq clients.
- **effort**: M (140-180 LOC: server_t* plumbing, cmq_sub_ref_t
  allocation per unique topic, MESSAGE-frame encode/decode on the
  bridge).

## P1 — CRL X509_STORE integration

- **gap** → `src/enterprise/cmq_tls.c:139` (CA loaded via
  `SSL_CTX_load_verify_locations`; CRL path stored by
  `cmq_tls_set_crl` but never actually loaded into X509_STORE) →
  **impact**: revoked client certs accepted; the API exists but is a
  no-op. Real security hole. → **effort**: S (30 LOC: parse CRL with
  `X509_CRL_parse_file`, call `X509_STORE_add_crl` after the CA is
  loaded).

## P1 — MQTT QoS2 retransmit table

- **gap** → `src/enterprise/cmq_mqtt_server.c:373` (QoS 2 path emits
  PUBREC + PUBCOMP but no per-packet-id state; duplicate PUBREL
  accepted unconditionally).
- **impact**: lost PUBACK on QoS 1 / lost PUBCOMP on QoS 2 silently
  breaks at-least-once delivery; client retransmits, server has no
  memory of the original state.
- **effort**: M (per-session packet_id map, bounded size; cleanup
  on disconnect).

## P1 — Multi-listener: slots[1..3] wired

- **gap** → `src/server/cmq_server.h:99` (`CMQ_MAX_LISTENERS=4`) +
  `src/server/cmq_server.c:6675-6693` (only `slot[0]` built from
  legacy `tls_cert/tls_key/tls_ca`; slots[1..3] never assigned) →
  **impact**: cannot serve two distinct certs/ports from one process
  → **effort**: M (accept loop iterates `tls_config_slots[]`, each
  binds its own port + fd; cmq_rch handles for the new slots).

## P2 — Async WAL ring backpressure leak

- **gap** → `src/store/cmq_filestore.c:712` (producer
  `cmq_filestore_async_enqueue` blocks on `async_not_full` if ring is
  full; no bounded wait, no stats counter for "publisher stalls") →
  **impact**: a slow worker stalls publishers indefinitely with no
  visibility → **effort**: S (add timeout, stat counter).

## P2 — Subject_rl atomic hash collision analysis

- **gap** → `src/server/cmq_subject_rl.c:55` (FNV-1a 64-bit hash of
  subject only; two subjects with same hash both get full admit; with
  10K subs collision probability ≈ 10K^2 / 2^64 ≈ 5e-12 — negligible,
  but no test covers adversarial hash collisions)
- **impact**: theoretical bypass of rate limit if collisions cluster
  → **effort**: S (add a unit test that constructs the colliding
  inputs and asserts the limit still holds).

## P2 — cmq_rch_handle abuse (no leak test)

- **gap** → `src/util/cmq_rch.h` (no UAF / leak test; release_owner
  only drops the initial ref, unbalanced acquire/release paths
  untested)
- **impact**: silent UAF on reload races → **effort**: S (write
  `test_rch_overflow` that intentionally double-releases + acquires
  beyond initial; assert no UAF under ASAN).

## P2 — STATS replay counter under handle_publish failure

- **gap** → `src/server/cmq_server.c:6798` (replayed counter
  increments on entry to `replay_one_record`, BEFORE handle_publish
  runs; if handle_publish returns -1 the counter is still ticked)
- **impact**: `stat_messages_replayed` overcounts by malformed-record
  count → **effort**: S (move increment to after successful
  handle_publish).

## P3 — MQTT retained-message delivery on SUBSCRIBE

- **gap** → `src/enterprise/cmq_mqtt_server.c:341` (SUBSCRIBE records
  topic via `cmq_mqtt_record_subscriber` but never reads
  `cmq_mqtt_fetch_retained` to deliver stored messages)
- **impact**: MQTT retain semantics broken — new subscribers don't
  get the last retained message for their topic → **effort**: S
  (after SUBACK, walk recorded topics and emit PUBLISH).

## P3 — 5.0 properties decode on PUBLISH/SUBSCRIBE

- **gap** → `src/enterprise/cmq_mqtt_server.c:120` (CONNECT 5.0
  property length skipped; PUBLISH/SUBSCRIBE property length NOT
  parsed at all)
- **impact**: 5.0 clients sending response_topic /
  message_expiry_interval / user_properties get these silently
  dropped → **effort**: M.

## P3 — Persistent retain store

- **gap** → `src/enterprise/cmq_mqtt_server.c:113` (g_mqtt_retained
  is process-local; restart loses retained messages)
- **impact**: QoS 0 retain state is ephemeral → **effort**: M
  (retain file under persist_dir, write on store_retained, load on
  cmq_server_create).

## P4 — Publish path quota/subject_rl instrumentation

- **gap** → `src/server/cmq_server.c:2965-2974` (handle_publish
  call gates; no `stat_*` increments on rejection beyond `stat_publishes_rejected`)
- **impact**: ops can't distinguish subject-rl-blocked vs
  quota-blocked messages → **effort**: S (separate counters).

## P4 — HEALTHZ endpoint reflects async WAL state

- **gap** → `src/server/cmq_server.c:5185` (HEALTHZ returns
  config presence; doesn't report filestore health, async ring
  backlog, or reload state) → **impact**: k8s probes can route to a
  wedged server → **effort**: S.
